# 框架介绍与 React 常见术语

## 1. 简介

React 是一个用于构建用户界面的 JavaScript 库，它有以下三个特点：

- **声明式**：React 使创建交互式 UI 变得轻而易举。为应用的每一个状态设计简洁的视图，当数据变动时 React 能高效更新并渲染合适的组件。
- **组件化**：React 可构建管理自身状态的封装组件，然后对其组合以构成复杂的 UI。由于组件逻辑使用 JavaScript 编写而非模板，因此开发者可以轻松地在应用中传递数据，并保持状态与 DOM 分离。
- **跨平台编写**：React 不仅适用于开发客户端应用，还适用于 Node 端进行应用的服务器渲染。

## 2. React 常见术语

### 2.1 组件（Component）

从概念上类似于 JavaScript 函数。它接受任意的入参（即 `props`），并返回用于描述页面展示内容的 React 元素。组件也允许将 UI 拆分为独立可复用的代码片段，并对每个片段进行独立构想。

React 有两种定义组件的方式：**函数式组件** 和 **类组件**。掌握了函数组件的能力，使函数组件可以更优雅的方式替代类组件后，在开发中更推荐使用函数组件。

### 2.2 JSX

JSX 是一个 JavaScript 的语法扩展。JSX 可以很好地描述 UI 该呈现出的交互并且具有 JavaScript 的全部功能。JSX 编写的组件通过预处理器 babel 解析后，再交给 React 库渲染到指定容器下，形成最终的 HTML 页面，供浏览器解析和显示。

### 2.3 属性（props）

组件接收的入参即为组件的属性（props），组件的属性（props）是不可修改的。父组件通过属性（props）向子组件传递数据。

### 2.4 状态（state）

任何的状态总是所属于特定的组件，可以通过 `this.setState()` 方法来修改状态（state）值。

### 2.5 组件生命周期

React 严格定义了组件的生命周期，生命周期可以经历如下三个过程：

1. **装载过程（Mount）**：也就是组件首次在 DOM 树中渲染的过程。
2. **更新过程（Update）**：组件被重新渲染的过程。
3. **卸载过程（Unmount）**：组件从 DOM 树中删除的过程。

React 会在对应生命周期阶段，调用组件的内置成员函数，即生命周期函数，例如：`constructor`、`componentDidMount`、`render`、`componentWillUnmount` 等。

### 2.6 上下文（context）

context 是 React 中一种跨组件层级共享数据的方式，可以在不通过 props 传递数据的情况下，将数据传递给任意深度的子组件，提供了一种简便而强大的方式来实现跨多个层级共享和管理状态。

### 2.7 Effect 生命周期

Effect 在 React 中定义为由渲染引起的副作用：

1. 每个 Effect 与周围组件有着独立的生命周期。
2. 每个 Effect 描述了一个独立的同步过程，可以开始和停止。
3. 在编写和读取 Effect 时，要独立地考虑每个 Effect（如何开始和停止同步），而不是从组件的角度思考（如何挂载、更新或卸载）。

### 2.8 客户端渲染（CSR）

页面 HTML 的组装，由浏览器完成的模式，页面的数据由服务端提供。常见的单页面应用（SPA）都是客户端渲染模式。

### 2.9 服务端渲染（SSR）

SSR 是一种在服务器上预先生成页面的技术，与客户端渲染不同，页面的组装由服务端完成，数据也是服务端提供，客户端只负责展示页面内容。与客户端渲染（CSR）相比，具有以下常见优势：

1. 更快的首次内容绘制（First Contentful Paint, FCP）。
2. 更好的搜索引擎优化（SEO）。
3. 减轻客户端负担。
4. 更好地利用服务器资源。
