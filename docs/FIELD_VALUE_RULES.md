# 单数据源字段取值规则

完整配置及任务阶段示例见 [字段映射示例](FIELD_MAPPING_EXAMPLES.md)。

任务规划与后端实现共用 `agents/field_value_prompt_rules.py` 中的英文取值规则；`agents/field_value_prompt_rules_cn.py` 是仅供查阅的中文对照，不参与运行时导入或注入，修改规则时同步维护两份内容。保留原始契约字段名。明确允许依赖缺失的业务分支先按已确认说明执行，其余必需输入缺失再适用缺值策略；非法输入、空结果与上游失败不能混作缺值。后端执行的契约语义缺口使用 `contract_mismatch`，任务类型边界或授权路径缺口使用 `plan_mismatch`，均要求具体 `change_request`。

字段映射沿用原有数据来源选择及“更换数据源”入口，不增加场景 Tab。每个 Endpoint 在工作台绑定一张数据表、一个外部 Operation，或自身持有的一份静态 JSON 内容；多字段依赖不等于多数据源。

## 静态数据

- 选择“静态数据”后依次展示数据来源、数据内容和返回字段三张卡片，不展示接口映射说明、数据库操作、查询条件或外部入参。
- 在独立的数据内容卡片录入 JSON 对象或同构对象列表，点击“校验并应用数据”后更新草稿。数据内容在编辑态默认折叠、详情态默认展开，保存校验失败时自动展开，折叠不丢失未应用输入。未应用修改阻止暂存和确认；应用内容不等于正式确认。返回字段仍来自现有 Endpoint 契约，绝不根据 JSON 改写接口契约。
- `sourceBinding: {sourceType: "static"}` 标识接口内的静态来源；`staticData` 保存完整 JSON。静态字段保存为 `sourceFields: [{sourceType: "static", path, type, description}]`，`[]` 表示数组项。不创建目录数据源、连接、物理快照或新端点；继续使用 `/endpoint-designs/run` AG-UI 保存及确认链路。
- 返回字段复用直接映射、固定值、接口参数及业务处理规则。直接映射保持数组层级；转换或聚合使用明确的业务规则。JSON 修改后保留原映射并提示失效路径，不静默重新绑定。
- 当前 JSON 编辑器要求字段名为字母、数字和下划线（不能以数字开头或使用原型保留名称）；列表项须同结构同类型。空对象、空数组和 null 因无法推断来源类型不接受。限制 256 KiB、12 层、每个列表最多 1000 项，数值不得超过 JavaScript 安全数值范围。
- 返回预览计算静态字段直连、固定值及用户试填的接口参数，保留数组顺序、零值和布尔值。直接依赖接口参数时弹窗按类型校验，参数按请求区域和路径区分，试填值不保存到配置；包含业务规则时不执行也不返回部分结果。
- 正式 JSON、Markdown、门禁复检与冻结契约保留静态内容。任务生成只需要后端对象、应用服务和控制器职责，不创建 Repository、上游 Client 或种子表；该内容是用户配置的正式数据，不是 mock。
- 编辑态返回字段默认折叠，详情态展开。未填写接口映射说明时不增加空说明卡片。

## 交互

- 查询条件保留列、运算符、值来源、参数及一层 AND/OR 分组。
- 数据库写入和外部 API 入参按目标字段配置。一个接口入参可供多个目标复用。
- 外部 API 可选入参仅在 `externalApiBindings` 包含对应目标时展示；移除即删除绑定，切换接口或重新加载后不自动恢复。编辑态通过“恢复参数”添加空绑定，再填写取值；必填参数始终展示且不可移除。可见状态不单独持久化。
- 接口参数只提供直接取值，不在下方提供“添加业务处理”。需要加工时选择“业务处理”，在独立弹窗中添加参与处理的字段，并填写自然语言规则；切换时保留原接口参数为初始依赖。
- 固定值使用目标字段类型；集合条件输入 JSON 数组。“内置参数”值来源选项置灰，不可选择。业务规则中的当前用户 ID、当前时间依赖仍由服务端可信上下文提供。
- 业务规则采用逐行“值来源 + 参与处理的字段”，支持添加、删除多项输入，参数按位置分组，同一字段不能重复选择；查询与外部入参只允许请求字段，返回处理可使用当前数据源字段。内置参数入口置灰。零输入可按业务规则独立生成。
- 规则弹窗及字段摘要均不展示“输入缺失时”、缺值策略和默认值控件，新规则沿用 `error`，编辑已配置规则时保留原缺值策略与默认值；存储与生成契约保持不变。
- 移除逐字段“业务入参用途”入口，改为可选的“接口映射说明”：用自然语言描述接口整体的校验、执行顺序、分支和返回处理。复用 `implementationDescription`（最多 4000 字符），随草稿暂存及正式映射确认，传入任务规划和代码生成；不填写不阻止确认，说明不得覆盖结构化契约或授权额外数据源。
- 规则显式应用前不替换原值。规则弹窗打开期间禁用外层暂存和确认，取消或关闭恢复原配置。草稿与正式确认边界保持不变。
- 浅色和深色样式共用工作台 `--wb-*` 主题变量。

规则使用 760px 独立弹窗，不占用条件行的参数列；输入行仅保留值来源、字段和删除操作，采用宽松分栏，窄屏上下排列。取消和关闭丢弃未应用编辑，应用后回到简短摘要。

### 业务规则输入来源范围

| 场景 | 接口参数 | 数据源字段 |
| --- | --- | --- |
| 数据库查询条件（查询、修改、删除） | 当前应用接口的请求字段 | 不提供，查询尚未执行 |
| 数据库写入字段（新增、修改） | 当前应用接口的请求字段 | 不提供，当前取值契约不支持读取已有行后加工 |
| 外部 API 入参 | 当前应用接口的请求字段 | 不提供，上游调用尚未执行 |
| 数据表返回字段 | 当前应用接口的请求字段 | 当前绑定表的字段 |
| 外部 API 返回字段 | 当前应用接口的请求字段 | 当前绑定 Operation 的响应体字段 |

- 接口参数按 Path、Query、Header、Body 分类，不包含本接口的返回字段，也不把外部 API 的请求目标当作可读输入。
- 值来源菜单仅显示当前场景中存在候选字段的类别；无请求字段时隐藏“接口参数”，无数据源候选时隐藏“数据源字段”。唯一保留的置灰类别是暂未开放的“内置参数”。
- 已被其他输入行使用的字段不可重复选择；没有剩余可选字段时禁用“添加输入”。允许零输入规则，不强制添加空行。
- “固定值”和“业务处理”属于目标取值方式，不是业务规则的输入字段类别；常量和处理过程写入处理规则。

## 当前契约

### 数据库映射 AI 辅助

- 查询阶段使用独立提示，只生成当前操作的完整条件树。按业务语义区分真实筛选与分页/排序等控制参数，参数选填不等于排除筛选；直接引用不增加处理规则，不推断缺值策略、默认筛选值或权限条件。明确的关键词任一匹配保留 OR 子组，与其余必须同时满足的筛选保留 AND，最多一层子组；信息缺失会改变完整筛选语义时整组留空提问，不删除部分条件凑结果。问题仅涉及查询，返回来源或统计返回值留给后续步骤。三种取值、原运算符及 v7 查询结构保持不变，生产提示中的分组示例经真实转换/组合校验回归覆盖（`tests.test_endpoint_design_assist_query`），不宣称真实模型效果已验证。

- 在常驻单表数据库工作台的编辑态开放页头“AI 生成映射”。绑定表并填写需求说明后可生成，无需先选操作；根据需求与契约识别单表 CRUD 后生成对应的全部可配置区域，不提供局部生成或逐项差异勾选。原草稿保留卡片顺序、折叠行为、页头暂存与正式确认；外部 API、静态数据的辅助范围见下节，完整复杂映射编辑器不开放此能力。
- 采用“生成完整映射 → 分区审阅结果 → 替换当前草稿”。首次输入为必填“需求说明”，空白时前端禁用生成且后端拒绝；后续待明确项的字段回答和其他说明才是可选补充，不能代替主需求。生成结果由专用只读视图展示“待明确、查询条件、写入字段、返回字段、映射说明”，按本轮识别操作隐藏不适用区域。预览期间隐藏原草稿卡片、禁止外层保存，可返回当前草稿继续编辑。查询树共享一组表头，通过关系标识保留整体 AND/OR 语义；映射说明直接展示精简全文，不再重复摘要和完整说明。
- 复用独立 `/endpoint-designs/run` 的 `generate_mapping`、`refine_rule`、`replace_mapping` AG-UI 动作。`generate_mapping.instruction` 为必填主需求，`clarification` 单独传递可选的字段回答和其他补充，两者合计最多 4000 字。操作识别仅接收正式接口的方法、路径、名称和说明、当前表身份及需求/补充，不接收请求、返回或表字段清单；后续查询、写入和返回步骤继续按区域接收真实字段及本轮新操作。旧操作和旧映射仅用于平台基线校验和撤销，不进入操作识别提示。不读取业务记录或连接密码，不执行 SQL、脚本、命令或文件写入。
- 点击一次生成后，后端按“识别数据库操作 → 查询条件 → 写入字段 → 返回字段 → 映射说明”自动串行调用模型，跳过 CRUD 不适用步骤；前端通过原 AG-UI 阶段进度展示当前步骤，全部完成后统一预览。操作使用独立提示，以明确业务用途和契约为主要依据，接口名称、HTTP 方法和路径仅作辅助；影响操作的契约/补充冲突、物理/软删除歧义或无法表达的复合写入需提问。此步骤只收集操作歧义，已明确软删除属于修改，具体标记字段和取值在写入步骤核对；不因字段取值、查询条件或返回来源未明确而暂停操作识别，不猜测枚举。操作有歧义时以正常完整生命周期返回 `mapping=null`、`operation=null`、`operationReason` 和问题，不进入后续步骤，不开放替换。用户补充后整套重新生成。
- 生成前只展示“API 契约＋绑定表”、按需展开的输入详情、补充要求和生成按钮。生成后操作在上下文行展示，输入和判断依据合并为折叠详情；分区默认优先展示待明确项，没有问题则进入首个可配置区域。完整生成结果的 `mapping.databaseOperation` 随全部配置一并替换，经后端按新操作重新校验；原草稿用于基线比较和一次撤销。
- 待明确问题根据完整返回字段身份归并，同一字段的模型问题和平台“未配置”提醒共用一项；短叶名称只有在当前返回契约唯一时才关联，无法关联的问题保留为其他待明确信息，不推测归属。返回表的待明确入口定位对应补充框。按字段回答与其他补充独立于主需求传递，共同参与整套重新生成，与主需求合计上限 4000 字；结构化输入身份参与结果失效及阶段重试校验，不能因两类文本拼接相同而复用旧结果。回答本身不直接配置字段，也不将未配置项标为已解决。当前单表无法确定的字段可暂留未配置，替换后手工补全，不自动引入跨表来源。
- 每个步骤使用独立中文短提示和简洁 JSON 示例，不向模型展开领域 JSON Schema。输入为可读契约和字段清单；输出包含本区域目标、`inputs` 字段引用、明确的固定 `value` 或自然语言 `rule`、问题。固定值、业务规则及自增列显式写入需附简短 `basis`；缺少依据则留空提问，查询条件整组留空，不能删除其中单项改变 AND/OR 语义。后端按真实元数据补齐身份、类型及快照，再执行现有 v7 校验；不接受模型自写来源或隐藏策略。
- 后续步骤接收本轮已完成区域的可读摘要及问题，不把未生成区域或未决问题当作事实。当前表的真实主键、自增、可空、默认值约束进入提示和元数据基线；缺少属性显示未知，数据库默认值不自动转为固定写入。返回步骤不能仅凭列存在假定新增后已经取回自增值。
- 生成结果通过 `reviews` 展示取值依据，查询以整组审阅。前端 `MappingAssistReview` 将筛选规则、固定值或业务处理的依据放在对应查询组/目标字段旁折叠展示，直接映射不重复解释，不堆叠全局依据清单。AI 依据仍需人工审阅，结构校验不代表业务正确；依据不进入正式映射或持久化草稿。
- 修改补充要求或问题回答后保留上一次预览，并提示“补充内容尚未用于生成”；替换按钮与应用函数同时阻止旧结果应用。重新生成成功后解除限制，已经用于生成的字段回答和补充说明保持可查阅与修订。失败、取消保留已填回答，切换接口清除该接口的临时回答。
- 模型或步骤校验失败时，标准 AG-UI 失败结果附带 `assistFailure`（失败阶段、已完成阶段、`retryToken`）；阶段包含 `operation`。用户可明确选择从失败步骤继续，`generate_mapping` 接受该凭据。服务端仅复用本轮已验证的操作判断与前序结果，缓存只在进程内保存十分钟且最多三十二项，凭据一次性消费；输入、草稿、版本或表约束变化、凭据过期或服务重启均需重新完整生成。修改要求或补充答案也整套重跑，不猜测其影响范围；取消或失败始终不回填部分结果，不自动重试。
- 生成和替换均从空配置确定性组装：覆盖查询、写入、全部返回字段、说明及其中规则；未知返回项标为 `unconfigured`，不继承旧固定值、业务规则或隐藏策略。模型不得新增内置依赖或隐藏默认值；默认缺值策略为 error。CRUD 越界、重复目标、伪造字段或不匹配快照均拒绝。update/delete 查询或 create/update 写入缺失时只允许作为未完成草稿，并返回问题，正式保存仍受完整校验阻止。
- 生成绑定 Endpoint、来源、操作、草稿、TechnicalPlan/正式映射版本及表结构。生成期间可继续编辑，编辑使原建议失效；切换接口或取消后丢弃迟到回执。应用期间锁定表单和保存，失败保留草稿，重试由用户重新发起。
- 待明确区使用独立字段卡片，紧邻字段展示未配置状态、具体问题、补充规则和暂留未配置说明；其他补充说明独立分区并默认展开。结果区底部集中展示“补充并重新生成”和整体替换操作，输入变化、总字数上限及运行互斥继续控制可用性；操作尚未明确时只提供重新生成，不显示替换入口。点击替换后列出将置为未配置的返回字段，再由用户确认整体回填。确认绑定当前生成与补充要求，内容变化后旧确认不可执行。应用只回填原有内存草稿，展开涉及区域并标记，回执集中展示“尚未保存”及撤销入口；一次撤销仅在未继续编辑、暂存、确认或切换目标时可用。辅助结果不持久化、不增加正式格式字段，仍使用 v7；正式产物仅由原保存确认生成，开发仍需原“确认并检测”。
- 原业务规则弹窗增加“AI 完善规则”。已选依赖保持不变，候选仅完善说明；采用只修改编辑框，点击原“应用规则”后才回填草稿。取消丢弃未应用内容，隐藏缺值策略与默认值始终保留；查询/写入不得读取尚未返回的数据表字段。
- 回归：`tests.test_endpoint_design_assist`、`tests.test_endpoint_design_assist_stream`，`tests.test_endpoint_design_assist_operation` 仅模拟模型和权威读取，覆盖操作识别到真实转换/编排/替换、歧义停止、重试和取消；纯同步回归为 `tests.test_endpoint_design_assist_steps`、`tests.test_endpoint_design_assist_retry`，直接连接约束投射由 `tests.test_api_design` 覆盖。前端聚合入口 `apiDesign.test.ts` 包含辅助 model/runtime，以及 `mappingAssistHooks.test.tsx`、`ruleAssistHooks.test.tsx` 的真实 React 18 hook 回归；`mappingAssistTestHarness.tsx` 只模拟 AG-UI 服务端，不替换生产 hook。聚合运行器沿用项目已有的 React 外置方式，避免 act 打包产生常驻 MessagePort。本次验证限制：不执行前端测试、构建、`/health` 与 Electron 验证；允许前端类型检查及后端聚焦回归，实际结果以交付报告为准。

### 外部 API 映射 AI 辅助

- 绑定单个外部 Operation 后，编辑态通过同一页头“AI 生成映射”进入。必填需求说明与后续可选补充说明分开传递，合计最多 4000 字。生成仅依据应用 API 契约、当前外部 Operation 的公开结构和用户要求，不继承旧草稿的取值或规则。
- 后端自动串行生成“外部入参 → 应用返回字段 → 映射说明”，逐步校验后统一预览，不进行数据库 CRUD 识别。请求阶段的目标使用 `external:区段:路径`，只允许当前应用请求参数作为字段输入；返回阶段的目标使用应用返回标识，字段输入仅允许当前外部响应体字段及应用请求参数，保留数组路径 `[]` 的语义。
- 每个目标采用直接取值、明确固定值或自然语言业务处理之一。固定值与业务处理必须提供来自契约或用户要求的简短依据；来源身份、字段快照和类型由平台依据当前结构补齐。拒绝请求响应方向混用、跨来源依赖、重复或不存在的目标、类型冲突及模型自定义的隐藏缺值策略。
- 当前目录读取仅提供 Operation 方法、路径、名称、说明和字段元数据；不执行外部调用，不向模型提供连接配置、认证值、请求响应样例或旧草稿。提示词仍集中于 `agents/endpoint_design_assist_prompts.py`，按处理目标、业务概要、需求、补充、前序结果和可用输入组织；映射说明仅消费本轮摘要。
- 预览包含“待明确、外部入参、返回字段、映射说明”。未确定的外部入参保持空取值，未确定的应用返回保持 `unconfigured`；外部请求问题按完整目标标识关联，避免同名请求与返回混淆。整体替换确认列出未配置的入参与返回，回填后可手工补全或移除不使用的可选外部参数，必填参数仍受原确认校验约束。
- 共用 `/endpoint-designs/run` 的 `generate_mapping`、`refine_rule`、`replace_mapping`，由 `selection.sourceType` 分派严格请求模型。能力元数据通过 `mappingAssistSourceTypes` 声明数据库和外部 API，通过 `externalMappingGenerationSteps` 声明外部三步流程；事件仍为 `endpoint-designs`，状态快照仍为 `endpointDesigns`，成功及已处理失败均保持完整 AG-UI 生命周期。
- 生成、显式失败重试和整体替换绑定工作区、Endpoint、来源、当前草稿、正式契约/映射版本及外部结构摘要。生成期间编辑使结果失效，切换目标或取消后丢弃迟到结果；失败步骤仅在同一基线下恢复本轮已验证的前序步骤。替换重新读取权威结构，只返回内存草稿，由原 `edit()` 一次回填并展开涉及卡片，支持一次撤销；不写正式映射、不推进开发，正式生效仍走原保存确认与主流程复检。
- 外部入参和返回的原业务规则弹窗共用“AI 完善规则”。候选只完善文字，不增删已选依赖；入参不能引用外部响应，返回仅可引用当前外部响应及应用请求。采用后仍需点击原“应用规则”，弹窗打开期间继续禁止外层保存。
- 后端聚焦回归为 `tests.test_endpoint_design_external_assist`、`tests.test_endpoint_design_external_assist_stream`，覆盖真实转换与校验、部分草稿、版本冲突、提示输入隔离、不写正式文件、失败重试、取消和三动作生命周期；模型与元数据读取均受控模拟，不访问真实模型或外部服务。前端 `externalMappingAssist.test.tsx` 由 `apiDesign.test.ts` 聚合，覆盖分区预览、同名目标隔离、替换/撤销和迟到结果；按本次要求保留测试代码但不执行前端测试、构建、`/health` 或 Electron 验证，允许类型检查及后端聚焦回归。

### 静态映射 AI 辅助与 Mock 数据

- 静态来源使用两个独立入口。页头“AI 生成映射”依据已应用的静态字段结构、API 契约和必填需求生成返回映射；没有有效数据时先手工应用 JSON，或在“数据内容”卡片点击“生成 Mock 数据”。静态模式仍只包含数据内容和返回字段，不增加数据库操作、入参写入或接口映射说明。
- 静态映射复用 `generate_mapping/refine_rule/replace_mapping`，仅有 return 生成步骤。模型只接收 `static:路径` 和应用请求参数的可读结构，不接收静态值、旧映射或旧规则。短引用由平台补齐路径快照，直接取值核对类型及 `[]` 层级；固定值与业务处理仍需要明确依据。未知返回项进入原待明确区，整体预览/替换和一次撤销沿用既有交互；替换映射时校验静态内容保持生成基线，不能借此生成或修改数据。
- Mock 使用同一 `/endpoint-designs/run` 的独立 `generate_mock_data`、`apply_mock_data` 动作，结果位于 `mockData`，继续使用 `endpoint-designs` 事件和 `endpointDesigns` 状态快照及完整生命周期。能力声明增加 `staticMappingGenerationSteps`、`mockDataGenerationSteps` 与 `mockDataMaxRows`，来源支持包含 static；不新增 REST、IPC 或正式持久化字段。
- Mock 需求必填，每组列表条数可选 1–20，默认 3。模型仅依据当前应用返回契约、样例需求及条数生成虚构内容，不读取旧静态值或真实业务记录，不生成映射。数据必须完整匹配返回契约的路径与类型，保持同构列表，并满足已有静态 JSON 的 256 KiB、12 层、合法字段名和安全数值限制；空容器、null、额外或遗漏字段、类型不符及条数不符均不能应用。
- Mock 在卡片内展示 JSON 预览、待明确问题及已有映射可能失效的提示。“应用到数据内容”先重新校验契约版本、正式映射版本、草稿与内容摘要，再一次回填当前内存数据，保留原有返回映射供审阅。应用不自动生成返回映射；需要时再点击页头 AI 入口。数据回填后展开卡片、标记尚未保存，允许撤销一次；后续手工编辑、映射应用、暂存、确认或切换目标使撤销失效。
- Mock 与映射生成互斥，候选预览及运行期间锁定外层保存。手工 JSON 未应用时禁止 AI 操作，避免覆盖输入；外部回填即时更新编辑基线，不能把短暂渲染状态当作用户未应用修改。取消关闭标准 AG-UI 请求，切换 Endpoint/来源或草稿变化后迟到候选不能应用，失败保留需求和当前草稿，由用户显式重试。
- 静态业务规则弹窗也支持 AI 完善，仅使用已选静态路径、应用请求或原有内置依赖，候选采用后仍需原“应用规则”才改草稿。AI 不增加依赖或隐藏策略，规则编辑期间继续禁止外层保存。
- 本次按用户要求不新增测试用例，不运行自动测试、类型检查、构建、`/health`、Python 编译检查或 Electron 验证，由用户手动验证。浅深主题使用现有 `--wb-*` 变量，实际视觉和模型联调未验证。

正式 JSON 和草稿格式均为 `endpoint-field-mapping.v7`，不提供历史读取、迁移或双写。

`sourceBinding` 保存当前选定表或 Operation 的身份，避免所有返回字段都是业务生成时丢失来源选择。它不是第二份数据源配置；实际元数据仍来自数据源目录。

`databaseQuery.items[].right`、`databaseWrites[].right`、`externalApiBindings[].right` 和 `fieldMappings[].right`（`mappingType=value_mapping`）共用取值契约：

| kind | 内容 |
| --- | --- |
| endpoint | `endpointField`，必须是当前 Endpoint 的完整请求字段快照 |
| fixed | `value`，与目标类型及条件运算符形态匹配 |
| business | `origin`、`endpointFields[]`、`builtinFields[]`、`businessDescription`、`missingBehavior`、可选 `defaultValue` |

`origin` 仅用于恢复接口参数 / 内置参数 / 业务生成的编辑状态。所有业务取值以完整依赖清单和处理说明为准，平台不执行用户表达式或脚本。

`missingBehavior` 为 `error`（报错）、`omit`（省略目标值，查询时跳过该条件）或 `default`（使用类型匹配的默认值）。默认值仅在 `default` 下允许；数值零和布尔 false 均为有效值。外部必填参数禁止 `omit`。

外部请求目标统一保存在 `externalApiBindings: [{ externalField, right }]`，不再由应用请求侧的 `source_mapping` 表示。每个目标唯一，输入可复用。调用前的规则禁止依赖该次调用尚未返回的响应。

数据源返回加工继续使用 `source_mapping`、`sourceFields[]`、`processingType` 和 `businessDescription`，并增加缺值策略。`business_description` 继续表达应用入参的纯业务用途。确认时检查依赖快照、来源范围、目标唯一性、类型和必填覆盖。

## 下游消费

独立 `/endpoint-designs/run` AG-UI 流保存草稿和确认后的 Markdown/JSON 双文件，不推进主工作流。修改规则后必须再次确认，开发门禁继续通过显式“确认并检测”复检。

Markdown、只读详情、冻结契约、构建任务输入和业务验收均保留完整规则。生成代码在数据源调用前计算请求值；数据库固定值和加工结果均参数化，不生成 SQL 字符串片段。update/delete 的所有条件因缺值被省略时必须报错，禁止执行无条件修改。
