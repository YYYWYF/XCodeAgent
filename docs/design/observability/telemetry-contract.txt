1. 消息和交付
请求体：schema_version、batch_id、sent_at、records。record.data 按 record.type 二选一，不能把两套数据同时塞进同一条记录。
观测记录使用一套本地持久队列，异步批量上传自有后端；不依赖 LangSmith 云端导出、存储或二次采集。
这是观测数据接收合同，不修改任何现有产品 AG-UI、Workflow、Checkpoint 或恢复协议。本文不实现上传接口。
发送端至少一次交付：相同 record_id 的内容不可变化，重试必须保留原身份与时间，不能重复捕获同一事实后重新生成随机 ID。
接收端按经过认证的用户/组织边界加 record_id 幂等；在 records 全部可靠持久化后才返回成功，临时网络/5xx/限流失败才重试；格式/语义错误应定位到 record_id 并隔离诊断，不得无限重试坏记录阻塞整条队列；413 分批重组保留 record_id。正式 ACK/错误返回结构仍需在接收 API 中明确。不按数组位置或到达顺序去重/排序。
鉴权和授权取传输层；不能仅信任消息体 user_id。repo_id 是去凭证后规范化仓库地址得到的稳定标识，不上传仓库凭证或 Workspace 路径。

2. 字段规则
时间：所有时间为 UTC RFC3339，使用 Z 后缀；duration_ms、ttft_ms 等单位毫秒。时长由单调时钟测量，时间戳用于关联。
公共字段均必须出现；不适用的可空字段填 null。result 与 context.extra 内的阶段特有字段按需出现；未列出的字段不接收。
null 是未知/不适用，0 是已测得的零，不能互相替代。缺失数据不能纳入平均值后当零处理，报表应显示采集覆盖率。
execution_trace：model 只在 span_kind=model 时出现；active_intervals 只在 span_kind=workflow 时出现。result 是真实业务摘要，按需出现。
Trace 是已完成/中断的不可变记录。待用户确认的根执行应在等待边界关闭，确认后用新的 run_id/Trace 继续，同一业务操作保留 operation_id。
活跃区间在已知边界持久化；异常中断没有可靠结束或活跃区间时填 null，不能用上传时间补结束或推测耗时。
project_id 必须取应用稳定身份 application.id；当前代码存在缺失/可覆盖入口，接入采集时必须补齐一致性，不宣称现在所有链路已满足。
conversation_id 是用户可见对话 ID；thread_id 是实际执行线程，两者不要求相等。没有实际执行的应用/会话创建事件允许 thread_id/run_id 为 null。
operation_id 是必要的新增观测关联字段：一个独立业务操作从开始、澄清、确认到恢复完成保持不变；Trace、开发启动/完成及最终失败记录必须填写。仅用于跨 Run 分析，不接管业务运行机制。
change_id 只取正式修订身份。mode 取实际选择的 Ultra/Pro/Fast，未启用模式时 null，不按模型名猜。

3. LangSmith / LangChain 来源映射
LangSmith id -> span_id；name -> run_name；start_time/end_time -> started_at/ended_at。保留原生调用树时直接映射 parent_run_id/trace_id；过滤包装 Span 时，parent_span_id 必须重连最近保留祖先，所有 trace_id 统一到选定根，不能指向永远不会上传的父节点。
原生 run_type=llm -> span_kind=model；tool -> tool；Graph root/node 由真实平台执行边界标注，普通 chain 包装不虚构 Node。
LangSmith status=success/error 是技术状态；平台统一为 completed/failed，取消、等待用户及中断由平台生命周期提供，业务通过与否另看 result.outcome。
原生 session_id 是 LangSmith Tracing Project ID，禁止映射为本合同 conversation_id 或 project_id。
input_tokens/output_tokens/total_tokens 从模型 usage 元数据取得。只统计真正的 model Span，禁止同时累加父 Node/根 Span 的聚合用量。
流式首输出证据 -> ttft_ms；输出间隔 output_duration_ms 需要采集器记录首/尾输出，不保证 LangSmith 导出自动包含该字段。
active_intervals、result、业务 Metadata、所有 Telemetry Event 均为本平台补充，不能标为 LangSmith 自动提供。
模型错误时 usage 可能缺失；SDK 内部隐式重试可能未展开为独立 Trace，本合同不要求或承诺完整的物理请求/重试明细。
官方依据：https://docs.langchain.com/langsmith/run-data-format
官方依据：https://docs.langchain.com/langsmith/log-llm-trace

4. 指标口径（后端计算，不上传累计总数）
用户数：取现有账号系统。活跃用户：周期内主动提交 request 的 user_turn_submitted.user_id 去重；回答/确认单列，不混入主动发起口径。
新建应用数：application_created 中 creation_source=new_app，按 project_id 去重；重新打开/导入已有工作区不能当新建。
对话数：conversation_created 按 conversation_id 去重，包含自动创建和用户创建；技术线程切换/长上下文续接不新增对话。
累计有效使用时间：按所统计的用户/对话/应用，合并 workflow 根 Span 的 active_intervals 重叠区间，求并集时长。不累加父子和并行 Span，也不计算 created_at 到 last_active 的自然时间差。
有效区间包含正在执行的模型、工具、节点及它们的实际调用等待；排除纯用户等待、暂停、未开始执行的队列时间。并发执行相同 10 秒，在使用时长中计 10 秒，资源耗时另按各 Span 分析。
对话平均耗时：对话累计有效时间 / 纳入统计的对话数；自动创建但确实没有执行的空对话计零，采集缺失的对话不能计零，应单列覆盖率。
发布应用数：先按版本身份找首次成功时间，筛选周期内首次成功的版本，再按 project_id 去重；相同 SHA 重推不重新产生版本创建事实，也不改变归属周期。
版本数：成功提交并推送后的 project_id + repo_id + commit_sha 去重；创建分支、启动发布、失败推送都不计。相同 SHA 重推不新增版本。按该事实的最早成功 occurred_at 归属周期。
这沿用需求中“提交并生成版本”的发布定义，不代表部署上线。代码依据 Backend/app/services/version_publish.py::publish_version。
首版本边界：完整采集的新应用最早成功 application_version_created.occurred_at，由事实时间计算。既有/导入应用的首个观测发布不等于真实首版本；首版本报表只纳入创建与首发事实完整的新应用，禁止按批次到达顺序或布尔值判断。
应用平均完成耗时：已产生首版本的应用，从创建后到首版本边界前的有效执行区间并集时长取平均。首版本之后继续使用的时间计入累计使用，不计入首版本完成耗时。
应用平均对话数：同一首版本完成应用集合，汇总创建到首版本边界前创建的 conversation_id 数量取平均。
页面/API数：主报表统计截至截止时点累计完成过的数量，含未发布应用。页面按 project_id + target.id，接口按 project_id + target.api_contract_id + target.id 去重；重复完成和后续删除/返工不改变累计数量。周期新增需先找全量可信记录中的首完成时间再筛周期；本期不要求当前存量清单快照。
Token总量/模式分布：provider 来源的已知 Token 分量只汇总 model Span，每个 span_id 一次；失败调用返回的已知 usage 也计入。estimated 单列，缺失部分单列覆盖率；完整总 Token 只取 usage_status=complete。
应用平均 Token：使用与首版本完成耗时相同的应用集合/首版本边界，汇总各应用创建后、首版本前结束的模型调用 Token；若有跨边界调用不随意按秒分摊，应单列。usage 不完整的应用不能当完整成本，给覆盖率。
TTFT：逻辑模型调用开始到首个非空生成输出；非流式/未观测填 null，统计可用样本的分位数，不用平均总耗时代替。
输入/输出窗口 TPS：窗口内结束的模型调用 input_tokens/output_tokens 合计除以窗口秒数，是应用侧完成量吞吐，不是 Provider 输入预填充速度。
单次流式输出 TPS：output_tokens / (output_duration_ms / 1000)，仅 provider usage、流式首尾证据且 duration > 0；不等于窗口吞吐，分开命名。
QPS：窗口内开始的逻辑 model Span 数 / 秒数。并发数：该时刻 started_at <= t < ended_at 的模型 Span 数。用户确认本期使用结束记录做事后报表，按真实开始时间回补 QPS、按已知区间回放历史并发；无需实时开始事件。SDK 隐藏重试不计为已观测 Provider QPS。
生成/写入代码行数按真实计量事实汇总；代码入库结果及其时机、周期汇总和去重由用户已有算法提供，不在本方案设计本地/远端认定。code_committed 承接结果并关联真实提交，不额外规定每份结果都可相加；未知行数单列。
代码入库率：直接上传用户已有算法的 code_inclusion_rate 结果；跨应用聚合同样沿用既有方式。本方案不定义或重算分子、分母、模板来源与权重；repository_code_lines/studio_code_lines 仅在原算法提供时记录。
首轮成功/修复/测试/验收：取 result 的实际首轮/修复/最终结果，但 operation_id + node_name 不能自动区分并行 Unit 或新候选，独立业务样本及修复链关联尚需补齐。显式重试最终成功不抹掉历史失败事件，也不能回填成之前自动修复成功。
业务 attempt 从 1 开始，仅模型输出返回后因 JSON/schema/质量失败重新生成才递增；SDK 网络/限流自动重试不递增。不同职责的 run_name 单独分析。
requirement_document_ready 是 RequirementSpec 与 ProductPlan 联合候选准备完成，不是两个独立完成事实。
workflow_failure 是最终业务失败；已自动恢复的瞬时异常只保留 Trace。event_category=failure 不因错误抛出多次就多计失败。
thread_handoff 只记真实跨业务对话交接，来源在 identity；普通 Retry/Resume 和独立新对话不制造交接边。
execution_thread_continued 只记已实现且真实发生的超长上下文线程续接，不把关心该能力理解为已实现。
application_profile_updated 只从已确认文档/权威配置得到画像；缺少分类结果可为 null，不为埋点额外调用模型。

5. 应用层语义校验（JSON Schema 本身无法表达全部跨字段关系）
同一 record_id 内容冻结；跨批次同一 span_id 只计算一次。根 Trace parent_span_id=null 且 trace_id=span_id；子 Span 的 trace_id 必须等于对应根。
ended_at 不早于 started_at；有效区间不倒置且位于根 Span 已知边界内。duration_ms 为实际单调时钟时长，不强制等于受校时影响的 UTC 差值。
usage_status=complete 时三个 Token 分量均非 null，且 total=input+output；partial 至少一项非 null 且不是全量；unavailable 三项均 null。
usage_source=unavailable 时 usage_status=unavailable；其余来源不可凭空填数字。ttft_ms 非 null 时不得超过已知模型 duration_ms。
目标 endpoint 必须有 api_contract_id；其他目标 api_contract_id=null。开发完成/启动事件必须有真实 context.target。
代码入库结果的业务去重按用户已有算法；传输记录仍按 record_id 幂等。同一版本成功事实按 project+repo+SHA 去重，重复 push 时间不覆盖首次成功。
代码入库相关数值均由用户已有方法提供，语义由该方法负责；本方案只校验既定字段类型和编码范围，不额外推导比例或强加聚合算法。
user_turn_submitted、conversation_created、handoff、context续接必须有 conversation_id；Trace 必须有真实 run_id 和 workflow_scope。后台 Worker 继承原应用与发起用户身份。
目标操作和失败记录必须保留真实 operation_id；用它聚合跨 Run 成功/失败，不从 run_id 临时猜操作身份。
版本 completed_artifacts 是对应 SHA 的平台确认完成快照，页面/接口列表内部去重。版本提交是短时间同步读快照，禁止用之后更新的 lifecycle 覆盖旧版本快照。

6. 每个字段的用途与类型
下面的字段是完整可接收清单。common 字段必须出现，其他是否必填按 Schema required 与条件约束为准。

最外层请求对象（没有 batch 字段）
  schema_version [固定 1]：本消息的字段合同版本；不等于产品或应用版本。
  batch_id [string]：一次上传请求的 ID；相同批次重试复用，重新组批可变化。幂等依据是 record_id。
  sent_at [string]：本次实际发送时间，便于观察队列和上传延迟。
  records [array<record>]：一批独立事实记录；聚合指标由后端计算，不上传会不断增长的用户总数/应用总数。

records 数组中的单条对象（没有 record 字段）
  record_id [string]：记录的稳定唯一 ID；上传、队列重试均复用。Trace 由 span_id 稳定生成，Event 由事件名与业务事实 ID 稳定生成，不能每次回调重建随机 ID。
  type [string (execution_trace / telemetry_event)]：只有两个采集来源类型；model/tool/node/workflow 在 Trace 内细分。
  occurred_at [string]：该事实实际发生时间；Trace 为终态记录形成时间，不使用上传时间替代。
  producer [producer]：见 #/$defs/producer
  identity [identity]：见 #/$defs/identity
  context [context]：见 #/$defs/context
  data [object]：按 type 区分的 Trace 或 Event 内容。

producer
  source [string (frontend / backend / worker)]：实际产生记录的进程类型。
  environment [string (development / test / production)]：运行环境，避免开发与生产数据混算。
  platform [string (macos / windows / linux)]：操作系统，用于比较平台故障与性能。
  xcodeagent_version [string]：事实发生时的 Studio 产品版本，不能在上传时替换为当前版本。

identity
  user_id [string]：现有账号系统提供的稳定用户 ID；后台任务沿用发起者身份，不上传登录 token。
  project_id [string]：本合同中代表应用的稳定身份，即 application.id；跨会话、分支和版本不变。不另设 application_id。现有缺失或可覆盖的入口必须在接入采集时补齐，不能按路径或分支名猜测。
  conversation_id [string | null]：用户可见业务对话的稳定 ID，用于统计对话数；同一对话可以拥有多个实际执行 thread_id。不是 LangSmith 的 session_id（Tracing Project ID）。
  thread_id [string | null]：实际执行使用的 LangGraph/AG-UI 线程 ID，可能与可见对话的线程不同。
  run_id [string | null]：一次真实业务执行的 ID；不是模型 Span ID，也不是 LangSmith Trace ID。
  operation_id [string | null]：平台为一次独立业务操作分配的观测关联 ID；同一目标过程的澄清、确认、自动修复及显式恢复共享，新业务目标或重新生成的新候选过程使用新 ID。用于跨 Run 计算成功率，不用于路由或恢复决策。
  change_id [string | null]：所属 Formal Revision ID；普通生成、普通聊天及非正式修改为空。
  workflow_scope [string | null]：实际执行入口，例如 application_planning、conversation、workbench、ui_generation；沿用实现的确定值。

context
  business_stage [string | null]：稳定业务阶段，例如 requirements、ui_design、technical_planning、build、unit_test、acceptance；应用创建等非阶段事实为空。
  node_name [string | null]：实际 Workflow Node 名称；不是自行推测的阶段名。非 Graph 业务动作可以为空。
  execution_kind [string | null (initial / resume / revision / retry / regenerate / repair / null)]：本次执行业务原因；没有执行上下文的应用/会话事件为空。
  attempt [integer | null]：本次具体业务生成请求的尝试序号，从 1 开始；成功返回但校验不通过后的重生成递增，Transport Retry 不递增；不适用时为空。
  mode [string | null (ultra / pro / fast / null)]：事实发生时实际选用的产品模式；不可按模型名反推，未启用模式时为空。
  target [target | null]：当前应用、页面、接口或实体目标；没有明确目标时为空。
  extra [object]：只允许已登记的阶段补充字段；不适用字段省略，不上传完整 state。

target
  type [string (application / page / endpoint / entity)]：开发或修改目标类型。
  id [string]：目标的稳定业务 ID；应用目标使用 project_id。
  api_contract_id [string | null]：Endpoint 所属 API Contract ID；其余目标为空，避免不同 Contract 下同名 Endpoint 混算。

execution_trace
  trace_id [string]：整个技术调用树的稳定 ID，独立于业务 run_id；未部署 LangSmith 也由采集器保留。
  span_id [string]：当前模型、工具、Node 或 Workflow 执行片段的稳定 ID。
  parent_span_id [string | null]：直接父 Span；根 Span 为空，用于还原 Node/Model/Tool 调用树。
  span_kind [string (workflow / node / model / tool)]：本平台的规范化类型 workflow/node/model/tool；不是 LangSmith run_type 原值。llm 映射 model，tool 映射 tool；Graph 根调用及真实节点由平台边界标注，不能把所有 chain 回调都当成业务节点。
  run_name [string]：当前片段实际承担的职责；模型如 requirement_analysis，工具如 read_file，Node 使用实际节点名。
  started_at [string]：执行开始时间。
  ended_at [string | null]：执行结束时间；进程崩溃且无法确定结束边界时为空。
  duration_ms [integer | null]：当前 Span 端到端持续时间，优先单调时钟；不是应用有效使用时长，不能跨父子 Span 相加。
  status [string (completed / failed / cancelled / interrupted / awaiting_user)]：本平台规范化的执行终态；不直接复制 LangSmith status。技术完成仍需结合 result.outcome 判断业务是否通过。
  active_intervals [array | null]：仅 workflow 根 Span 填写实际执行区间，排除等待用户回答/确认、暂停及尚未开始执行的排队。[] 表示确知没有执行；null 表示区间缺失，不能当 0。按统计对象合并重叠区间。Node/Model/Tool 不重复填写。
  model [model]：见 #/$defs/model
  error [error | null]：实际技术异常；没有异常时为空。
  result [result]：真实业务结果摘要，可用于模型输出校验或 Node/Workflow 结果；不能从模型正常返回自动推断业务成功。

active_interval
  started_at [string]：一段真实 Agent 执行的开始时间。
  ended_at [string]：该段执行停止、结束或转入纯用户等待的时间。
  duration_ms [integer]：该段非等待的实际执行毫秒数，优先使用单调时钟计时。

model
  provider [string]：实际调用的 Provider 或网关标识，不含地址、凭证。
  name [string]：实际发送请求的模型标识。
  input_tokens [integer | null]：实际输入 Token；未获得 usage 时为空，不填 0。
  output_tokens [integer | null]：实际输出 Token；未获得 usage 时为空。
  total_tokens [integer | null]：输入与输出 Token 之和；只有数量已知时填写。
  usage_source [string (provider / estimated / unavailable)]：Token 数据来源：provider 为模型返回，estimated 为显式估算，unavailable 为未获得；正式 Token 指标只使用 provider，估算单列。
  usage_status [string (complete / partial / unavailable)]：complete 为 input/output/total 均完整，partial 为仅部分分量可知，unavailable 为全部未知；未知数值为 null，不能填 0。
  ttft_ms [integer | null]：当前逻辑模型调用开始到首个非空生成输出的时间；包含开始后实际发生的前置网络等待/重试。需要流式首输出证据，只有角色头/空 chunk 不算；非流式或缺失证据时 null。
  output_duration_ms [integer | null]：流式首个非空输出到最后一个非空输出的实际间隔，采集器用单调时钟测量；不是 LangSmith 原生固定字段。未观测、非流式或没有有效间隔时为 null，不用总耗时冒充。

error
  layer [string (model / tool / validation / transport / system)]：错误所属层：model/tool/validation/transport/system；由已知异常或业务结果确定。
  code [string | null]：已有稳定错误码，无法确定时为 null，不从错误文案猜测。
  message [string]：实际错误信息的脱敏摘要；不上传凭证、完整 Prompt 或源码。

result
  outcome [string (succeeded / failed / blocked / awaiting_user / cancelled / skipped)]：已确认的业务结果；技术 Trace 无异常不等于业务成功。
  first_attempt_passed [boolean | null]：该业务操作在当前 node/阶段的首轮校验、Build 或测试是否通过；取首轮真实结果，不由最终成功倒推，用于首次有效率/首轮通过率。不适用或未观测时 null。
  repair_rounds [integer]：已发生的业务修复轮数，不含网络重试。
  test_summary [test_summary | null]：单元/集成测试统计，不适用时为空。
  review_issue_counts [object | null]：代码审查问题数量，按严重程度分类；没有做审查时为空。
  quality_gate_passed [boolean | null]：当前最终质量门禁是否通过；没有该门禁时为空。
  acceptance_decision [string | null (accepted / rejected / revision_requested / null)]：用户实际验收决定；还未作决定或不适用时为空。
  cache_hit [boolean | null]：Workspace Inspection 是否命中缓存。
  code_graph_status [string | null (available / degraded / unavailable / null)]：Code Graph 可用性；没有扫描时为空。
  unit_reuse_count [integer | null]：DAG 规划复用的 Unit 数。
  unit_generation_count [integer | null]：DAG 规划需要生成的 Unit 数。
  task_count [integer | null]：本次确定的 Task 数量。
  capability_escalated [boolean | null]：SmallTask 实际是否升级到更大的处理能力；未发生该类执行时 null。

test_summary
  passed [integer]：通过的真实测试/检查数。
  failed [integer]：失败的真实测试/检查数。
  skipped [integer]：明确跳过的真实测试/检查数。

completed_artifacts
  page_ids [array<string>]：本次版本成功生成时实际已完成开发的页面清单；不含仅规划的页面。
  endpoints [array<completed_endpoint>]：本次版本成功生成时实际已完成开发的接口清单；接口以 Contract 与 Endpoint 联合标识。

completed_endpoint
  api_contract_id [string]：Endpoint 所属 API Contract ID。
  endpoint_id [string]：已完成开发的 Endpoint ID。

context.extra
  clarification_round [integer]：当前已发生的业务澄清轮次，从 0 开始。
  question_count [integer]：上一轮实际要求用户回答的问题数。
  retry_reason [string]：输出返回后发生业务重生成的真实原因；不代表 SDK 网络重试。
  reference_template_id [string | null]：开发目标实际选用的参考模板 ID，未使用时 null。
  has_element_context [boolean]：此次操作是否携带选定页面元素上下文；不上传 DOM。

telemetry_event.data
  event_name [string]：以下登记事件名。
  event_category [business / failure / handoff]：业务/最终失败/交接三类；workflow_failure=failure，thread_handoff=handoff，其余=business。
  payload [object]：仅填写对应事件定义的字段；空定义传 {}。

application_created：应用创建事件，不依赖后续是否成功调用模型。
  creation_source [string (new_app)]：仅真正新建应用产生此事件；导入已有工作区不计新建。

conversation_created：只统计用户可见业务对话；只读查询、控制动作的临时 AG-UI thread 不算对话。
  creation_source [string (automatic / user)]：阶段静默建立或用户主动建立；两者都计入图中的对话数。

user_turn_submitted：系统正式接受一轮用户输入后产生；同一接受事实使用稳定 record_id 去重，技术重试不算新的用户轮次。
  turn_kind [string (request / clarification_answer / confirmation / feedback)]：用户实际提交的本轮输入类型，允许按口径筛选活跃用户。
  input_modalities [array<string (text / image)>]：仅记录文本/图片类型，不上传输入正文、截图或图片内容。
  image_count [integer]：本轮提交的图片数量。
  has_element_context [boolean]：是否提供已选页面元素上下文；不上传 DOM 或源码。

development_target_started：正式接受并启动 Page/Endpoint/Entity 开发一次；目标放在公共 context.target，避免按 Model Call 数量统计启动比例。
  payload={}；时间/目标/身份已由公共字段给出。

request_classified：记录真实路由结果，支持二次修改进入设计/规划/开发的比例。
  request_kind [string]：实际已确定的请求分类，例如 casual_chat、workspace_question、implementation_fix、formal_revision。
  route_stage [string]：最终已确定的目标业务阶段；确定性路由同样记录。

requirement_document_ready：一份新的联合需求文档确实准备完成；同一版本只计一次。
  document_id [string]：RequirementSpec 与 ProductPlan 联合需求文档的稳定 ID。
  artifact_revision [integer]：本次交付用户评价的文档版本。
  clarification_round [integer]：形成该版本时已完成的澄清轮数。

artifact_reviewed：支持接受、修改、重新生成比例；联合需求文档保持共同确认的原业务门禁。
  artifact_id [string]：用户正在评价的正式候选产物或联合需求文档 ID。
  artifact_type [string (requirement_document / ui_design / technical_plan / build_task_plan)]：被评价的业务产物类型。
  artifact_revision [integer]：被评价的准确产物版本。
  decision [string (accept / revise / regenerate / skip)]：系统实际接受的用户决定；不记录无效或过期按钮点击。
  user_edited [boolean]：确认时是否发现并同步用户对 Markdown/候选内容的实际修改。

ui_design_action_accepted：UI 模板采用、重生成、调整与跳过的产品行为；后续执行质量从 Trace 关联。
  action [string (select_template / regenerate / adjust_pages / skip)]：系统实际接受的 UI 设计操作。
  page_ids [array<string>]：本次操作涉及的页面。
  template_id [string | null]：选用的参考模板 ID；未选模板时为空。

revision_impact_decided：Formal Revision 批准率及返工层级分析；change_id 关联同一正式修改。
  decision [string (approved / rejected)]：正式修订影响范围被实际批准或拒绝。
  affected_artifacts [array<string (requirement_spec / product_plan / ui_design / technical_plan)>]：后端最终确认的受影响产物集合。
  earliest_stage [string]：当前影响分析最终确定的最早回退阶段。

control_action_accepted：只记录平台接受的控制事实，不接管或新增 Recovery 机制。
  action_id [string]：实际已接受的控制动作 ID，避免重复回调重复计数。
  action [string (stop / pause / retry / resume)]：实际控制操作。
  target_run_id [string]：被控制的原执行 ID。
  target_node_name [string | null]：原系统签发的目标 Node 名称；不适用时为空。
  child_run_id [string | null]：实际创建的新执行 ID；没有创建新执行时为空。

development_artifact_completed：真实首次完成事实；页面或 Endpoint 身份在 context.target；继承已有完成状态不重复记一次新完成。
  payload={}；时间/目标/身份已由公共字段给出。

application_version_created：应用当前提交并推送流程成功后记录。版本事实按 project_id + repo_id + commit_sha 去重，首版本为该应用最早成功事实；不使用分支数、虚构版本号或 is_first_version 布尔值。
  repo_id [string]：目标仓库稳定标识，不上传含凭证的 URL。
  branch_name [string]：该版本对应的 Git 分支。新建空分支本身不计版本。
  commit_sha [string]：成功推送的完整 Git SHA，与 repo_id 和 project_id 一起标识版本；同一 SHA 重推不增加版本数。
  completed_artifacts [completed_artifacts]：见 #/$defs/completed_artifacts

code_generated：代码生成行数，与已写入和已入库分开；不上传生成的源码。
  model_span_id [string]：对应的真实 Model Span ID。
  generated_lines [integer | null]：现有计量方法得到的 LLM 生成代码行数；无法计量时 null，不能填 0。
  measurement_method [string]：已有代码计量/归因方法的标识，便于判断是否可比较。

code_written：真实写入成功后记录；同一写入事实使用稳定 record_id，重试不重复计数。
  model_span_ids [array<string>]：已识别的来源模型 Span ID，未识别为 []；不为了填充而猜测来源。
  written_lines [integer | null]：实际写入文件的 LLM 代码行数，沿用已有计量方法；无法计量时 null，不能填 0。
  measurement_method [string]：既有计量/归因方法标识。

code_committed：承接用户已有算法提供的代码入库统计结果，并关联真实提交；入库时机、去重和汇总沿用既有算法，发布成功仍由 application_version_created 表达。
  repo_id [string]：仓库稳定标识。
  branch_name [string]：本次 commit 所属分支。
  commit_sha [string]：代码统计结果关联的真实提交 SHA；是否纳入入库统计由用户已有算法决定，不能仅凭 SHA 自行认定。
  parent_commit_sha [string | null]：提交前基线 SHA，用于应用既有入库行数/归因算法。
  committed_lines [integer | null]：用户已有算法提供的入库代码行数结果，结果周期和累计/增量含义沿用该方法；没有结果时 null。
  measurement_method [string]：既有代码归因/入库率算法及统计范围的标识；本方案不重新定义算法。
  repository_code_lines [integer | null]：用户已有算法提供的仓库代码行数依据；仅原方法提供时填写，否则 null，本方案不预设其统计范围。
  studio_code_lines [integer | null]：用户已有算法提供的 Studio 代码行数依据；仅原方法提供时填写，否则 null，本方案不预设来源划分。
  code_inclusion_rate [number | null]：用户已有算法提供的比例结果，按合同以 0~1 编码上传；没有结果时 null，本方案不重算。

workflow_failure：真实业务失败与 Trace 中原始错误分工；后续用户重试成功不会删除原失败事实，使用 Run/Operation 关联。
  scope [string (operation / workflow)]：失败终态的业务范围，用 operation_id 或 run_id 聚合。
  failed_span_id [string | null]：对应失败 Span ID；Trace 未覆盖的故障允许为空。
  recoverable [boolean]：现有系统是否提供恢复条件；仅观测，不决定恢复。
  error [error]：见 #/$defs/error

thread_handoff：公共 identity 是来源；只记录明确的跨对话业务交接。普通 Retry/Resume 或独立打开新对话不制造交接边。
  to_conversation_id [string]：真实业务交接后的可见对话 ID；来源为公共 identity.conversation_id。
  to_thread_id [string]：目标对话对应的实际执行线程 ID。
  to_business_stage [string]：交接后的业务阶段。
  reason [string]：确定的交接原因，例如 stage_transition、formal_revision、revision_return。

execution_thread_continued：仅实际发生上下文超限技术续接时记录；identity.conversation_id 保持不变，不增加对话数，不为埋点新增续接功能。
  to_thread_id [string]：同一个可见对话续接后的实际 Graph 线程 ID。
  to_run_id [string]：实际启动的续接 Run ID。
  reason [string (context_limit)]：上下文长度达到限制后的真实续接。

application_profile_updated：形成有分析价值的应用场景画像；配置取 application.json，业务分类取已确认文档，不上传源码、文档正文或账户敏感字段。
  scenario_code [string | null]：已确认业务文档中可确定的场景分类；尚未有分类规则/结果时 null，不临时新增模型调用生成画像。
  scenario_tags [array<string>]：已有已确认文档能提供的业务场景标签；没有标签为 []，不上传需求全文。
  terminal [string | null]：已确认产物或应用权威配置中的终端类型；没有明确值为 null。
  datasource_type [string | null]：application.json 或已确认的数据源配置中的类型；不上传地址或凭证，不确定为 null。
  auth_enabled [boolean | null]：应用权威配置中的认证开关，不是 Studio 用户登录情况。
  authorization_enabled [boolean | null]：应用权威配置中的授权/RBAC 开关。
  source_artifact_id [string]：画像依据的已确认正式产物 ID。
