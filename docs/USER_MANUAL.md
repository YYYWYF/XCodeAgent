## 1. 先了解完整流程

DevAgent Studio 将应用开发分为六个阶段：**设计 → 计划 → 开发 → 测试 → 审查 → 验收**。

一次新应用的典型操作如下：

```text
登录桌面客户端
  → 新建应用并填写应用场景、项目位置和基础配置
  → 回答需求澄清问题
  → 联合确认需求分析与产品计划
  → 生成并检查 UI 设计稿，或明确跳过 UI 设计
  → 手动进入计划阶段
  → 审阅并确认技术规划，等待模板准备完成
  → 进入开发阶段，选择页面或接口任务
  → 配置关联接口的字段映射，点击“确认并检测”
  → 审阅任务计划，点击“确认并进入 Build”
  → 代码生成与构建检查，选择执行或跳过单元测试
  → 补齐应用全部必需开发产物后，确认进入测试
  → 测试通过后选择代码审查范围
  → 审查通过后确认进入验收，实际操作应用
  → 验收通过，提交并推送代码
  → 按需发起下一轮迭代
```

请区分以下操作的作用：

| 操作 | 实际含义 |
| --- | --- |
| 回答澄清问题 | 补充信息，系统据此生成或调整文档，仍需审阅确认 |
| 暂存 | 保存未完成配置，不能作为开发依据 |
| 确认正式文档 | 允许后续阶段使用当前这版文档；修改后需要再次确认 |
| 保存并确认接口映射 | 固化当前接口的映射版本，尚未启动开发 |
| 确认并检测 | 重新检查当前开发目标的接口映射，通过后继续规划任务 |
| 确认并进入 Build | 同意本轮任务范围，开始执行开发任务 |
| 切换阶段或查看产物 | 查看相应内容；是否能执行仍取决于当前确认状态和门禁 |
| 验收通过 | 用户认可本轮实际效果，解锁后续交付操作 |

## 2. 启动与登录

### 2.1 日常使用

1. 启动已安装的 DevAgent Studio 桌面客户端。
2. 在登录窗口点击登录按钮。
3. 按系统浏览器中打开的云效授权页面完成登录或授权。
4. 回到客户端，等待登录成功后进入主窗口。

登录窗口出现并不代表平台后端已经连接成功。若点击登录后提示连接失败，应先检查平台后端和认证服务配置。授权超时或已取消时，可重新发起登录。

桌面客户端的云效登录用于进入 DevAgent Studio；创建应用表单中的“认证”用于配置所生成应用的登录能力，两者分别配置。

当前登录过期后需要重新登录。窗口隐藏到托盘时会保留当前登录会话；真正退出客户端后会清理登录凭据，下次启动需要重新授权。

### 2.2 从本项目源码启动（开发环境）

普通安装包用户可跳过本节。源码运行需要先准备 Node.js、pnpm、Python、项目依赖和本机配置，详细要求见 [README](../README.md) 与 [云效登录接入](YUNXIAO_LOGIN.md)。

Windows 下，在项目根目录分别打开两个 PowerShell 窗口执行：

```powershell
# 终端一：启动 DevAgent Studio 平台后端。
.\scripts\start-backend.ps1
```

```powershell
# 终端二：启动 Electron 桌面客户端。
.\scripts\start-frontend.ps1
```

认证服务基址 `YUNXIAO_ENDPOINT` 由环境维护人员在本项目 `Backend/.env` 中配置。这里启动的是 DevAgent Studio 自身；后面“服务状态”抽屉启动的是正在开发的生成应用。

## 3. 新建应用或打开已有项目

### 3.1 新建应用

在欢迎页点击 **“新建应用”**，按表单填写：

| 配置分组 | 如何填写 |
| --- | --- |
| 项目位置 | 输入一个新的项目目录，或通过“选择文件夹”选择空目录。不能复用已有 DevAgent Studio 应用目录 |
| 基础信息 | 填写应用名称、终端类型、应用图标与应用场景。应用场景应说明目标用户、主要业务和希望完成的操作 |
| 码云地址 | 当前表单展示固定仓库地址，尚未开放自定义 |
| 版本号 | 填写本应用使用的远端分支名，例如 `v1.0`。此处“版本”对应 Git 分支 |
| 导航与菜单 | 选择左侧、顶部或混合导航，设置头部、底部、菜单开关和页面根路由。启用默认菜单或认证时，根路由不能为 `/` |
| 主题 | 选择生成应用的主题色；与工作台自身的浅色/深色切换分别设置 |
| 数据源配置 | 选择模拟数据库，或填写外部数据库信息。外部数据库支持表单中的 DBID 与账号密码连接方案 |
| 认证 | 按需要启用，并填写认证来源和一号通 clientId |
| 权限控制 | 涉及权限时启用，并填写真实的初始管理员成员标识。权限控制依赖认证，启用权限会同时启用认证 |
| 页面埋点、接口埋点 | 按组织环境填写开关、标识和地址；启用的必填项必须完整 |

应用场景示例：

> 为运营人员开发订单查询应用。需要订单列表与详情页，支持按订单编号和状态筛选，查看金额、客户及创建时间。本轮只做查询，不做订单新增、退款或删除。订单数据使用现有数据库，实际表字段在接口映射时配置。

完成后提交创建。系统检查表单与项目目录，并进入设计流程。若发现远端已有同名分支，会先要求确认覆盖；继续会覆盖该远端分支的代码，不确定时应取消并换一个分支名。

### 3.2 打开已有项目

- 在欢迎页“最近项目”中点击已有应用。
- 或点击 **“打开工作目录”**，从已保存项目中打开，也可添加带 `.devagentstudio` 目录的本地 DevAgent Studio 项目。

“打开工作目录”用于恢复受 DevAgent Studio 管理的项目。普通代码文件夹不能直接当作已完成初始化的应用打开。

### 3.3 从首页移除与删除项目

最近项目的删除入口提供不同处理方式：从首页移除只删除索引；删除本地项目会在再次确认完整路径后，将项目目录及关联聊天历史移至系统回收站，并移除索引。仅想整理首页时选择移除索引，之后仍可通过“打开工作目录”重新添加。

## 4. 认识工作台

| 区域 | 主要用途 |
| --- | --- |
| 顶部应用与版本区域 | 查看当前应用、切换查看版本、查看未提交文件和已完成模块；按当前状态执行提交或新迭代 |
| 顶部阶段条 | 查看设计、计划、开发、测试、审查、验收进度，回访已到达的阶段 |
| 左侧导航 | 进入临时对话、历史对话、推荐任务、数据源、外部 API、文件、技能、设置等入口；部分入口随阶段显示 |
| 对话区域 | 输入需求、查看进度、回答问题、确认文档、任务、修复范围和验收动作 |
| 右侧区域 | 查看预览、开发产物、应用文件，以及接口字段映射等内容；随阶段和所选内容变化 |
| 底部状态与恢复区域 | 查看连接问题、当前执行失败原因，以及系统提供的重试、继续或结束操作 |

“开发产物”中的页面或接口点击操作用于查看详情；要启动正式开发，可使用“推荐任务”中的页面或接口任务入口。打开文件或浏览产物不会自动切换阶段，也不代表该产物已完成开发。

历史对话用于查看已有执行和确认记录。继续处理任务时，应打开对应会话，读取当前状态并使用当前有效操作。旧确认卡片可能因文档或执行状态变化而失效。

顶部主题按钮切换工作台的浅色/深色模式；右侧区域可通过顶部按钮显示或隐藏。

## 5. 设计阶段：确认需求和 UI

### 5.1 回答需求澄清

系统根据应用场景提出需要补充的问题。按问题选择选项或输入说明，重点说明：谁使用、要完成什么、有哪些页面、页面展示哪些信息、可执行哪些操作，以及什么结果算成功。

避免只写“做一个管理系统”。如果有明确边界，应主动写出，例如“只读查询”“本轮不提供导出”“删除前必须二次确认”。权限相关问题要提供真实的管理员成员标识，不要用姓名或占位值代替。

提交答案后等待文档生成。**补充答案只提供信息，不等于确认生成结果。**

### 5.2 联合确认需求文档

“需求文档”节点包含需求分析（RequirementSpec）和产品计划（ProductPlan），二者一起审阅、一起确认。

1. 阅读需求分析，核对目标用户、业务范围、规则与权限诉求。
2. 阅读产品计划，核对页面、信息项、操作、跳转、加载/空/错误等状态和业务验收标准。
3. 有偏差时通过编辑入口或修改意见描述调整，等待新稿后再次检查。
4. 内容正确时点击 **“确认需求文档并设计 UI”**。

用户查看和编辑的正式文档为 Markdown。若通过应用文件编辑对应 Markdown，应先保存，再执行该阶段确认；系统会在确认时同步编辑内容并校验。不要直接修改内部 JSON 来替代确认。

这一阶段优先检查产品行为。数据库表映射、接口请求响应和技术实现方案在后续阶段处理。

### 5.3 生成和检查 UI 设计稿

进入 **“确认UI设计稿”** 后，可按页面选择模板生成，使用“换一换”生成或重新生成，也可使用全部生成入口处理尚未确认的页面。生成中的页面需等待结果，失败页面可按当前入口重试。

1. 按页面查看设计稿，检查布局、信息层次、按钮、表单、弹窗和交互反馈。
2. 实际尝试设计稿里的搜索、筛选、弹窗等本地交互。
3. 需要调整时输入明确意见，例如“订单列表筛选区改成单行，详情按钮移到操作列”。设计输入框可输入 `/` 指定目标页面。
4. 等待调整结束，重新核对受影响页面及其状态。
5. 按界面完成设计确认，并手动点击 **“进入计划阶段”**。也可明确选择 **“跳过 UI 设计”**，随后从阶段入口进入计划。

设计稿使用示例数据和本地状态表达视觉及交互，不连接真实业务接口。设计稿中能筛选或打开详情，不表示真实数据查询已经开发完成。

若跳过 UI 设计，后续页面依据已确认产品计划、技术规划和模板实现。若要新增页面、业务字段或操作，应先调整需求/产品计划，而不是仅在设计稿里增加内容。

## 6. 计划阶段：确认技术规划

进入计划阶段后，系统根据已确认的产品内容生成技术规划（TechnicalPlan）。

1. 阅读技术规划摘要及 Markdown 原文。
2. 核对前端、后端、数据架构是否符合项目条件。
3. 核对业务实体、字段、接口方法和路径、请求/响应结构，以及页面依赖接口是否完整。
4. 有问题时填写意见并点击 **“提交意见，调整技术规划”**，等待新稿再次确认。
5. 正确时点击 **“技术规划正确，进入工作区”**，等待模板生成或更新完成，再按入口进入开发阶段。

确认技术规划是初始化代码模板的前置步骤。模板准备期间请查看进度；若失败，使用底部当前失败项的重试入口。

技术规划确定“应用需要什么接口”，字段映射确定“该接口从哪里取数据、如何查询或写入、如何形成返回值”。二者都完成后才具备相应开发依据。

## 7. 准备数据源和外部 API

### 7.1 数据库与数据表

在左侧打开 **“数据源”**：

1. 新建或编辑数据库连接，填写当前连接方案要求的地址、端口、Schema、DBID 或账号密码等信息。
2. 对支持实时读取的直连 MySQL，点击 **“添加数据表”**，检索并选择要使用的表，可批量添加。
3. 在已添加表中打开详情，核对 Schema、表名和列信息。
4. 回到右侧字段映射，选择该已添加表。

当前数据库目录只允许一个数据库连接。只有已添加的数据表会进入简化映射的候选清单；“移除”只是移出应用候选，不会删除数据库中的真实表。

模拟数据库和 DBID 连接目前不支持这里的实时元数据读取。需要实时选表、选列时，应准备可访问的直连 MySQL。不要把创建表单里的“模拟数据库”与接口映射里的“静态数据”混为同一功能。

### 7.2 外部 API

在左侧打开 **“外部 API”**：

1. 先创建接口域，再在该域中新增接口（Operation）。
2. 在接口编辑界面填写方法、路径及请求、响应结构等信息，保存后查看详情。
3. 确认需要映射的请求参数和响应字段已完整描述。
4. 在右侧字段映射中选取这个外部 Operation。

当前按接口域展示平铺接口列表，界面不需要额外创建目录。查看字段结构读取的是已保存定义，不会自动调用外部服务验证业务结果。

删除数据源、接口或移除表前，系统会检查正式接口映射引用。若提示仍被引用，应先处理引用关系；不要假设删除来源会自动清除已有正式映射。

## 8. 配置接口字段映射

### 8.1 何时配置

可在右侧 **“字段映射”** 页签选取接口配置，也可先启动页面/接口开发，再点击门禁列表里的接口定位到同一工作台。页面开发会检查全部关联接口；单接口开发检查该接口；无接口依赖的纯静态页面直接通过这项检查。

门禁会展示目标范围内全部接口，包括已完成、待配置和已失效项。即使全部已经配置，也要点击 **“确认并检测”** 才会继续开发。

### 8.2 完成一次映射

1. 核对当前接口名称、请求方法、路径和请求/响应字段，避免配置错目标。
2. 选择来源：一张已添加数据表、一个外部 API Operation，或接口自身的静态数据。
3. 数据库来源：配置所需查询条件、写入字段和返回字段；外部 API 来源：配置上游入参取值和返回字段。
4. 对字段选择直接取值、固定值或业务处理规则。按界面先应用规则，再保存外层映射。
5. 需要补充整体实现顺序、事务或异常处理时，填写可选的“接口映射说明”；该说明不能代替必填字段映射。
6. 尚未完成时点击 **“暂存”**；完成并检查无误后点击 **“保存并确认”**。
7. 返回原开发会话，继续配置其他接口，最后点击门禁的 **“确认并检测”**。

一个接口在该工作台绑定一个数据来源。需要多来源编排或新增接口字段时，应先通过技术规划修订明确方案。更换来源可能清空当前草稿中的字段、写入和查询配置，请阅读更换确认提示。

### 8.3 字段取值与业务规则

| 场景 | 示例 |
| --- | --- |
| 请求参数作为查询条件 | 将应用接口 Query 中的 `status` 用作数据库状态列的过滤值 |
| 数据源字段作为返回值 | 将数据库 `order_no` 映射到接口返回的 `orderNumber` |
| 固定值 | 为目标字段设置符合类型的固定值，例如固定页大小 |
| 业务处理 | 选取参与处理的字段，写明“将分为单位的金额除以 100，保留两位小数” |
| 外部 API 入参 | 将本接口的请求参数绑定到上游接口要求的请求目标 |

同一请求参数可被多个目标复用。查询条件和上游入参只能依赖调用前已有的数据，不能使用本次调用尚未返回的响应。业务处理请写清输入、转换步骤和预期结果；当前“内置参数”直接选择入口置灰，不要将其作为可操作选项。

数据库修改和删除必须配置有效条件。规则编辑弹窗尚未应用时，外层暂存和确认会被阻止，应先应用或取消弹窗里的修改。

### 8.4 静态数据接口

选择 **“静态数据”** 后：

1. 在数据内容卡片输入 JSON 对象或同结构对象列表。
2. 点击 **“校验并应用数据”**。
3. 为当前接口已有返回字段配置来源，再点击 **“保存并确认”**。

例如，接口契约已有 `code`、`label` 返回字段时，可输入：

```json
[
  { "code": "pending", "label": "待处理" },
  { "code": "completed", "label": "已完成" }
]
```

静态内容是接口正式配置的数据，不是 UI 设计稿的模拟值，也不会据此自动新增接口字段。编辑器不接受无法推断类型的空对象、空数组和 null；当前限制为 256 KiB、12 层、每个列表最多 1000 项。返回预览支持直接取值等可确定结果，含业务处理规则时不执行该规则。

### 8.5 修改与失效处理

已确认映射可通过 **“修改映射”** 再编辑并确认。若技术规划中的接口契约变化，已有映射可能显示“需重新设计”，应按新字段补齐后再次确认、检测。

“暂存”“规则应用”“校验并应用数据”“保存并确认”“确认并检测”分别处于不同步骤，不可相互替代。旧实体绑定入口即使仍可见，也不能代替当前 Endpoint 字段映射或开发就绪检查。

## 9. 开发阶段：选择目标、确认任务并执行

### 9.1 选择页面或接口

1. 进入开发阶段，打开“推荐任务”，在“今天想从哪里开始？”区域选择页面或接口。
2. 核对所选页面，或接口的方法与路径。
3. 如有接口依赖，按上一节完成映射，点击“确认并检测”。
4. 等待工作区检查和任务规划完成。

选择目标用于限定本次开发范围。只完成一个页面，不代表应用其他页面和接口也全部完成。

### 9.2 确认任务计划

出现 **“任务计划待确认”** 后，展开本轮任务，核对开发目标、修改范围、任务依赖和验收标准：

- **确认并进入 Build**：同意当前计划并开始代码生成。
- **重新生成**：丢弃当前待确认规划，生成新的一轮；新生成失败也不会恢复旧待确认规划。
- **放弃当前规划**：结束这一轮待确认任务，保留聊天记录和已有正式计划。

任务生成期间可按当前运行入口取消整轮运行；待确认后使用确认卡上的动作。同一应用有正在生成或待确认的任务规划时，应先处理该轮，不要在其他会话重复启动任务规划。

### 9.3 执行和单元测试

确认 Build 后查看任务和构建进度。若涉及数据库执行、扩大代码范围或修复方案等确认，先阅读具体内容再操作。

构建检查后，系统会询问是否跳过单元测试：

- **“否，继续执行”**：生成或执行相应单元测试，查看结果及后续修复提示。
- **“是，跳过单元测试”**：明确记录跳过决定；跳过不代表测试通过。

Build 完成且单元测试关卡通过或被明确跳过后，才会登记当前目标的初次开发完成。仅看到代码文件或构建成功，不足以判断整个目标已完成。

### 9.4 补齐开发产物

系统按当前应用全部页面、接口和实体的状态判断能否进入测试，不只检查本轮 Build 所选范围。若确认卡列出“未完成产物”，按清单继续处理。

实体若在当前应用被计入阻塞项，按对应实体入口完成处理；界面允许跳过时需明确填写原因。跳过某个实体只作用于该实体，不会自动使其他产物完成，也不会替代接口映射。

## 10. 测试、审查与验收

### 10.1 测试阶段

1. 全部必需开发产物就绪后，在阶段确认卡核对测试目标并确认进入测试。
2. 查看构建、集成质量检查和测试报告。
3. 若出现前端性能测试选择，按本轮要求执行或明确跳过。
4. 失败时阅读具体错误，按当前界面的修复、确认或重试入口处理。

切换到测试阶段浏览不会自动启动测试；执行须通过正式确认。测试、审查和验收的可用性仍受应用当前开发完成情况约束。

### 10.2 代码审查

测试通过后，系统展示审查范围选择：

- **全量审查**：按全量范围检查项目代码。
- **Diff 审查**：检查已完成开发模块对应的当前变动文件，读取相关文件完整内容；没有可审查变动时按钮不可选。

检查问题报告，若要求确认修复范围或方案，确认后等待修复和复核。审查通过后，点击 **“进入验收阶段”**，系统会启动项目并进入验收流程。

### 10.3 人工验收

1. 在右侧实际应用预览中，按已确认产品计划的业务验收标准逐项操作。
2. 检查主流程、筛选、表单、跳转，以及加载、空数据和错误等状态；涉及权限时使用对应身份检查访问效果。
3. 满足要求后使用当前验收区域的 **“验收通过”** 或 **“验收通过并完成”** 操作。
4. 不满足要求时点击 **“不通过，进入对话”**，或使用当前计划提供的调整入口，描述具体问题并进入对应修改流程。

反馈示例：“订单列表输入不存在的编号后应展示空状态，现在仍显示上次结果。请保留现有接口结构，修复结果刷新。”

请用验收按钮提交决定。聊天中输入“通过”不能代替正式验收动作。验收通过也不会自动完成远端推送，交付还需执行“提交并推送”。

## 11. 运行预览与启动故障修复

### 11.1 手动启动与刷新

进入工作台只读取生成应用的服务状态，不自动启动其服务。开发中想查看实际应用时：

1. 打开右侧预览，在工具栏点击 **“服务状态”**。
2. 在抽屉中点击 **“重启服务”**，等待按后端、前端顺序启动。
3. 查看各服务状态、实际端口和失败摘要；没有后端工程时会显示无需启动。
4. 启动成功后查看当前页面；需要重新加载页面时使用预览刷新。

“重启服务”会先停止再启动生成应用的标准服务，不修改代码。页面刷新只重载页面，不负责启动服务。返回欢迎页会在后台停止当前工作区的预览服务；再次打开应用后，需要时重新启动。

### 11.2 启动失败后的诊断修复

1. 在服务状态抽屉切换 **“前端 / 后端”** 日志，确认是哪一层启动失败。
2. 对当前可诊断的启动失败，点击 **“诊断并修复”**，系统创建对应开发会话。
3. 阅读修复 Markdown 计划，检查原因、涉及文件与操作范围。
4. 确认计划后执行。系统检查受影响代码并重新启动服务。
5. 若计划需要调整，提交意见后重新审阅确认；需要停止则使用当前停止入口。

每次启动修复流程最多派发 3 轮修复。停止会保留已经产生的修改，不自动回退代码。修复计划或相关代码变化后需要重新诊断与确认。

该入口处理应用启动失败。已运行页面的业务问题应在开发或验收对话中反馈。启动成功只说明服务可用，不会替代测试、审查或人工验收。

## 12. 继续修改应用

在工作台对话中直接说明问题与预期结果，系统会结合当前目标和工作区判断处理路径。

| 请求类型 | 示例 | 后续操作 |
| --- | --- | --- |
| 了解项目 | “订单查询现在调用哪个接口？” | 读取项目并回答，无需启动正式开发 |
| 局部实现修复 | “现有查询按钮点击后没有刷新列表，请修复。” | 对代码修改先确认实现范围，执行后查看受影响层检查结果 |
| 产品需求修订 | “新增订单导出，并增加导出权限。” | 确认影响范围，回到受影响设计节点，重新确认相关文档 |
| 技术方案修订 | “查询响应新增分页总数，页面业务目标不变。” | 确认影响范围，重新规划并确认技术内容及受影响配置 |

正式修订会按最早受影响的阶段重新处理。需求和产品计划仍联合确认；受影响 UI、技术规划和任务计划也须通过各自确认，再进入开发。若同时涉及认证或权限开关，应通过正式修订提出并确认，由系统在相应确认边界应用配置。

局部修改完成后不会自动启动预览，也不会因为一次静态检查成功就完成应用验收。请按需启动服务检查实际效果。

需要撤销代码时，应结合实际提交状态处理；停止、放弃草稿或重新生成计划都不意味着已经产生的代码会自动回滚。

## 13. 提交代码、查看版本与发起迭代

### 13.1 提交并推送

1. 完成本轮验收，确认当前版本与仓库信息。
2. 点击顶部 **“提交并推送”**。若按钮不可用，悬停查看阻塞原因。
3. 阅读对话框中的改动范围，填写变更说明。
4. 确认后查看“打包本次改动 → 创建提交 → 推送到版本”的进度和结果。

此操作提交本次全部改动并推送到应用对应分支。这里的“打包本次改动”是交付提交步骤，不是生成桌面安装包；推送成功也不表示应用已自动部署上线。

### 13.2 查看版本

通过顶部版本选择查看其他分支对应的应用资产。历史版本只读，阶段与 Agent 调度会锁定；要继续工作，点击 **“回到当前版本”**。

当前“版本号”代表分支名，不是 Git 标签。切换查看历史版本不会把旧代码自动恢复到当前开发分支。

### 13.3 发起新迭代

当前轮提交后，顶部入口变为 **“发起新迭代”**：

1. 点击入口，选择在当前版本继续，或新建一个版本。
2. 新建时输入未使用且合法的分支名，例如 `v1.1`。
3. 确认发起，系统回到设计阶段并使用新的对话记录。
4. 描述本轮新增或调整需求，重新经过相关设计、计划和开发确认。

新建版本会创建并尝试推送远端分支；若提示远端提交失败，按提示处理，不要仅凭本地版本已出现就认为推送成功。已有产物可能标注“旧迭代 / 当前迭代”，实际是否还需开发，以本轮产物状态和门禁清单为准。

## 14. 技能、规则文件和设置

### 14.1 技能

左侧 **“技能”** 支持按“用户 / 内置”分类查看，按名称、描述或目录搜索。用户技能可通过 **“创建技能”** 或 **“ZIP 上传”** 添加，并可编辑、启用、停用或删除；按当前界面权限操作。

技能适合保存重复使用的开发约束或方法。标注“即将开放”的按钮尚不可用。导入后若出现无效技能提示，应按具体错误修正，不要仅依据上传动作判断已可用。

### 14.2 文件与应用文件

左侧 **“文件”** 管理 Agent 核心规则文件 `AGENTS.md`，用于约束 Agent 的角色与工作方式。编辑后点击“保存”，并核对界面显示的文件位置。

右侧 **“应用文件”** 用于查看当前项目文件与正式 Markdown 文档。二者用途不同；不要将核心规则文件当作需求文档，也不要直接修改内部 JSON 来改变确认状态。

### 14.3 设置

左侧 **“设置”** 可查看或编辑当前界面提供的基础信息、导航、认证、页面/接口埋点与环境变量等内容，完成后点击 **“保存设置”**。

环境变量区分开发与生产值，变量名使用大写字母、数字和下划线，并以大写字母开头。涉及敏感值时使用加密变量入口。不要把密码、令牌或真实密钥写进需求文档、技能正文或提交说明。

设置保存成功后，仍需按变更影响检查模板、运行服务和正式文档状态。涉及正式产品能力的变化，通过上一节的正式修订流程推进。

## 15. 贯穿示例：开发一个订单查询应用

以下示例使用已有直连 MySQL 数据表 `orders`。实际页面、接口和字段以当前生成并确认的文档为准。

| 步骤 | 用户操作 | 检查结果 |
| --- | --- | --- |
| 1. 创建 | 登录后新建“订单查询”，选择空项目目录，填写新分支名，描述列表、详情、编号/状态筛选需求 | 应用进入设计流程 |
| 2. 澄清 | 明确本轮只查询、详情从列表进入、不做删除，补齐必要认证配置 | 系统生成需求分析与产品计划 |
| 3. 确认需求 | 核对页面信息、筛选项、详情跳转和空状态，联合确认 | 可以进入 UI 设计 |
| 4. 设计 | 生成列表和详情设计稿，检查布局、筛选和详情入口；确认后进入计划 | 设计稿使用示例值，尚无真实查询 |
| 5. 技术规划 | 核对查询接口的编号、状态请求参数及订单返回字段，确认技术规划 | 模板准备完成，可进入开发 |
| 6. 数据准备 | 在“数据源”配置直连 MySQL，将 `orders` 加入表清单 | 字段映射可选择该表及列 |
| 7. 映射 | 为查询接口配置请求到查询条件、表列到返回字段的映射；“保存并确认” | 接口已有正式映射，开发尚未自动推进 |
| 8. 开发 | 选择订单页面任务，在门禁处理全部关联接口，点击“确认并检测” | 系统生成本轮任务计划 |
| 9. 执行 | 核对范围，点击“确认并进入 Build”，构建后选择执行单元测试 | 当前目标按结果登记完成 |
| 10. 补齐 | 按未完成清单处理其他页面、接口及实体 | 应用测试入口可用 |
| 11. 测试审查 | 确认测试；通过后选全量或 Diff 审查，按提示处理问题 | 可以确认进入验收 |
| 12. 验收 | 实际查询存在/不存在的订单，筛选状态并打开详情，核对真实返回数据 | 满足标准后提交验收通过 |
| 13. 交付迭代 | 提交并推送当前分支；下一轮发起迭代，提出导出需求 | 新需求重新走确认流程 |

## 16. 常见问题与恢复操作

| 现象 | 处理方式 |
| --- | --- |
| 能看到登录窗口，点击登录却连接失败 | 检查 DevAgent Studio 平台后端是否启动、认证服务基址是否正确；恢复后重新登录 |
| 文档生成后没有继续 | 检查是否正在等待澄清、文档确认或阶段入口；回答问题后仍需确认正式文档 |
| UI 已完成但技术规划没开始 | 点击“进入计划阶段”；完成或跳过 UI 不会自动越过该入口 |
| 设计稿有数据，实际预览没有 | 设计稿使用示例值。检查实际接口开发、映射、数据连接和运行服务 |
| 表下拉没有需要的数据表 | 先在“数据源”添加表；确认使用支持实时读取的直连 MySQL，并核对 Schema |
| 接口映射无法保存 | 检查必填字段、查询/写入条件、类型和未应用规则；静态数据需先校验并应用 |
| 暂存后仍显示待配置 | 暂存是草稿；完成后点击“保存并确认” |
| 映射已确认，开发没有继续 | 返回原开发会话，点击“确认并检测”；保存本身不推进开发 |
| 接口显示“需重新设计” | 核对技术规划是否改变，按最新接口契约重新编辑、确认并检测 |
| 某个页面完成了却不能测试 | 查看应用级“未完成产物”清单，补齐其他必需项；仅本轮 Build 完成还不够 |
| 预览空白或连接不上 | 打开“服务状态”，查看实际服务状态，点击“重启服务”，失败时检查分层日志 |
| 服务已启动但业务功能不正确 | 在开发或验收会话描述复现步骤、预期和实际结果，进入实现修复或正式修订 |
| 网络恢复后仍显示失败 | 使用当前会话底部的同步/重试入口，先恢复权威状态，再按系统提供的动作继续 |
| 字段映射面板读取失败 | 使用面板内“同步状态”；需要重新加载时阅读放弃草稿提示，避免丢失未确认输入 |
| 旧确认按钮失效 | 回到当前会话读取最新状态，审阅最新版本后操作，不重复点击旧卡片 |
| 任务停止后仍看到修改文件 | 停止不会自动撤销已写入内容，结合实际文件和提交状态处理 |
| “提交并推送”不可用 | 查看按钮提示，检查是否尚未验收、仍有运行或未完成步骤 |
| 远端推送失败 | 检查仓库访问、网络和凭据，按当前错误处理；本地提交成功不等于远端成功 |

恢复入口依据当前执行状态提供“继续”“重试”等可用动作，不保证从每个内部步骤原样接续。连接中断后不要立即重复发送相同开发请求；先同步当前会话，判断原任务是否仍在运行或等待确认。

## 17. 操作检查表与进一步阅读

交付前检查：

- 需求分析与产品计划已联合确认，产品范围和验收标准明确。
- UI 已检查并完成确认，或已明确选择跳过。
- 技术规划已确认，模板准备完成。
- 关联接口映射为当前有效版本，开发前已执行“确认并检测”。
- 本轮任务计划已经确认，全部必需开发产物已完成或按允许方式处理。
- 测试和审查结果已查看；明确区分通过、失败和跳过。
