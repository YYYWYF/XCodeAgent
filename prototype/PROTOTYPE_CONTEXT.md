# 工作台原型领域规则

本文档只描述 `prototype/` 演示工程中的工作台状态、交互限制和剧本约束，不作为正式工程的架构规范。

## 核心层级

**应用**：用户持续维护和迭代的软件工程，是版本链的根。

**版本**：应用在一次完整制作周期结束后形成的不可变资产快照。版本生成后，原型中的所有产物、对话输入和工作流操作均应只读；新变更只能发生在后续迭代版本中。

**阶段**：单个版本内依次发生分析、计划、开发、测试、审查、验收六个阶段。验收阶段由用户在应用预览中主责，意见回流使用独立的验收对话，不复用审查对话，也不创建新的正式产物。顶部阶段条只表达正常的单向旅程；进入后续阶段后，前序阶段产物默认只读，用户主动点击已到达的前序阶段时才需要二次确认。

**生成版本**：生成版本不是第七个阶段，而是用户验收通过后的确定性终态动作。动作完成后固化当前资产快照并锁定版本，后续变更只能发生在新迭代版本中。

**产物**：前五个 Agent 阶段的正式产物固定为：分析阶段的需求文档、计划阶段的项目计划、开发阶段的页面/接口/实体、测试阶段的测试报告、审查阶段的审查报告。验收阶段不新增正式产物，只保存用户确认和可选意见。

## 阶段与 Agent 职责

### 1. 分析阶段 · 产品 Agent

产品 Agent 负责澄清业务目标、角色、流程和功能边界，只维护需求文档，不生成项目任务或决定技术实现。新建应用后进入分析阶段默认对话；需求文档生成或修改后必须由用户明确接受，澄清回答不能替代文档确认。确认后自动进入计划阶段。用户从后续阶段回到分析阶段时，直接在原对话继续聊天；接受新需求文档后，现有项目计划及其下游产物失效，并重新进入计划阶段。

### 2. 计划阶段 · 项目 Agent

项目 Agent 只读取已确认需求并维护现有项目计划。项目计划是页面、接口和实体产物清单及直接依赖关系的唯一来源。用户从后续阶段回到计划阶段时，直接在原计划对话中提出调整；接受新项目计划后，系统按稳定产物 ID 刷新开发清单并自动进入开发阶段：未变化产物保留状态，新增产物为“未开始”，内容或依赖变化的产物重新待开发，被删除产物移出当前清单，相关测试报告和审查报告失效。

### 3. 开发阶段 · 研发 Agent

研发 Agent 负责页面、接口和实体实现，以及单元测试、跨产物调用检查、完整构建和基础启动验证。一条开发对话可以同时拥有多个相关产物，并分别维护其状态。每个实际实现或修改的产物都必须拥有并通过对应单元测试，单元测试不可默认跳过；页面到接口或实体的调用、对话范围内联调、应用级构建与主路由冒烟检查也必须通过，开发对话才能完成。当前“模型”统一改名为“实体”；实体本轮只接入类型、目录、状态和依赖占位，不实现详细生成工作流。

### 4. 测试阶段 · 测试 Agent

测试 Agent 从完整应用视角读取需求文档、项目计划、开发产物和开发验证证据，覆盖适合 AI 执行的跨模块组合、完整构建启动、黑盒边界、异常恢复、核心业务串通旅程以及轻量性能或稳定性探测。测试阶段唯一正式产物是测试报告，不创建分组测试用例，也不逐条向用户输出详细用例。测试 Agent 负责测试、诊断、缺陷归属和报告，不直接修改开发代码；报告必须说明 AI 测试范围和未覆盖边界，不能替代行内专业测试人员的正式测试结论。

### 5. 审查阶段 · 审查 Agent

审查 Agent 只在最新测试报告合格且对应当前代码 revision 时进入，独立检查代码规范、安全、健康度、可维护性、项目计划一致性和交付完整性，唯一正式产物仍是审查报告。审查 Agent 默认只读代码，不在审查中静默修复。审查报告必须记录其消费的测试报告轮次和代码 revision；审查问题必须关联回具体开发产物和默认开发对话。修复造成代码变化时，原测试报告按影响范围失效，必须重新取得合格测试报告后再审查。审查通过后自动进入验收阶段。

## 对话与产物

**对话**：承载 Agent 上下文和工作流的 Session。一个对话可以生成并拥有多个产物，也可以只读引用其他产物。

**默认对话**：持有某个产物唯一编辑权的对话。从产物树选择产物时，应进入该产物的默认对话；多个产物属于同一默认对话时，选择它们不应切换到不同对话。

**正式对话的创建时机**：欢迎页“新建应用”表单中的确认动作只创建分析阶段默认对话并授权产品 Agent 开始需求分析；需求文档确认后再进入计划阶段默认对话。开发阶段不按项目计划顺序静默预建对话。首次进入开发阶段时，用户必须先从弹框选择一个产物，确认后才创建该产物的默认对话并取得写锁；此后点击尚无对话的灰色“未开始”产物也必须先确认。测试阶段在全部当前开发产物满足开发门禁后创建测试默认对话；最新测试报告合格后才允许创建审查默认对话；审查通过进入验收时创建独立应用验收对话。普通空白对话仍在收到 Agent 回复后才进入目录。

**开发阶段的推进方式**：开发产物按应用产物树的稳定顺序推进。首次选择使用应用产物树，适配大量页面、接口和实体；当前产物完成并变为绿色后，自动选择下一个未完成产物并弹出创建对话确认，用户确认后沿用既有规则恢复或创建该产物的默认对话。一个页面的直接接口或实体依赖可以在同一开发对话中获得写权限并共同实施。全部当前开发产物完成并通过单元测试、联调、构建和基础启动检查后，测试阶段才达到可进入条件；“是否具备进入条件”与“当前所在阶段”必须分开记录，未具备条件的后续阶段不可点击。

**开发产物依赖规则**：项目计划只允许“页面依赖接口”或“页面依赖实体”。页面可以同时依赖多个接口和实体；不存在接口调用实体、接口依赖页面、实体依赖接口等链路。静态依赖本身只决定实施顺序和上下文，不自动授予写权限；研发 Agent 必须通过当前对话的产物领取逻辑取得相关产物。

**开发对话的构建链节点**：开发对话按“读取项目计划和依赖 → 确定本对话产物 → 实现直接依赖产物 → 实现页面 → 生成或更新各产物单元测试 → 执行单元测试 → 检查页面调用 → 对话范围联调 → 应用级构建与基础启动检查”推进。构建节点产出 `code_changes` 变更集并按文件轮次渐进发射：先直接依赖产物、再页面、最后共享路由或配置；每个文件在右侧“应用文件”面板的内容区呈现单文件 Diff 写入过程（新应用全部为新增文件，Diff 内所有行都是绿色新增行，与“+N -0”统计一致）。消息中的“文件改动”卡以“接受”按钮确认当前文件，接受后才继续下一个文件；开发自验证完成后右侧可以切换为浏览器预览；待确认卡片的选项支持 `description` 悬浮说明。

**分析与计划文档的生成过程**：需求文档和项目计划分别在分析、计划阶段以 `code_changes` 变更集按行分块渐进发射。Diff 写入过程与确认交互和代码一致，都在“应用文件”面板完成，并由“文件改动”卡的“接受”按钮确认，不再出现独立的“确认保存”授权条。接受后内容区恢复文档编辑态，并按阶段规则自然推进。

**测试报告的生成过程**：测试报告是应用整体测试结论，不按测试用例分组展示。每轮报告必须绑定需求文档版本、项目计划版本和实际代码 revision，并记录当前轮次、总体结论（测试中/不合格/合格）、约束覆盖摘要、整体测试情况、缺陷清单与关键证据、受影响产物及默认开发对话、已知风险、未覆盖范围和下一步动作。缺陷清单必须明确缺陷编号、严重级别、缺陷描述、受影响产物和对应开发对话。当前视图展示最新报告，历史轮次保留用于追踪已解决、未解决和新发现的问题。

**测试缺陷返修循环**：测试报告不合格时，测试 Agent 将缺陷关联到具体页面、接口或实体，并把受影响产物标记为“待修复”，随后结束本轮测试并引导用户切回开发阶段。系统打开相关产物的默认开发对话，把最新测试报告作为只读输入资源附加到对话；研发 Agent 只处理本对话拥有产物对应的问题，修复后必须重新执行相关单元测试、页面调用检查、联调、构建和基础启动检查，产物转为“待复测”。所有本轮受影响产物修复完成后引导用户返回测试阶段，测试 Agent 基于上一轮报告、实际代码变更和当前应用生成新一轮报告。循环持续到最新报告合格，之后才进入审查阶段。

**右侧工作区面板**：右侧只有两枚 tab——“应用文件”在前、“浏览器”在后。“应用文件”是应用专属目录（`wh-branch-pms-new/` 下的文档与代码同树），内容区在左、目录树在右；目录树默认折叠，仅自动展开当前定位文件的祖先链，并支持整栏收起为窄条；内容区不重复展示路径栏（路径由目录树呈现），滚动条隐藏但保留滚动手势；“浏览器”承载页面预览。用户可见的正式文档统一放在 `docs/`（与 frontend/backend 平级）：`docs/requirement-spec.md`、`docs/project-plan.md`、`docs/code-review.md`；`.xcodeagent` 式内部工件目录不进入演示目录树，也不展示 README.md 等模板说明文件。

**文件内容区的 IDE 语义**：文档与代码一样只有源码视图，不存在 Markdown 预览态，也不会在编辑或确认后自动切换视图；只读文档仅禁止编辑（只读源码编辑器），可编辑文档展示同一编辑器并保留保存动作。

**产物状态机**：开发基础状态保持“未开始 → 进行中 → 已完成”。测试报告内部记录测试结论和缺陷关联，不另起一套测试质量状态视觉层；左侧产物视图继续只用统一状态圆点展示基础状态。测试发现缺陷时，把受影响产物从“已完成”重置为“进行中”，但不得抹掉产物已经完成过开发的历史。对话加载、工作流执行、目录刷新等瞬时状态不得让产物闪回“未开始”。

**目录信息顺序**：顶部阶段条、产物视图和对话视图统一使用 1/2/3/4/5 表示分析、计划、开发、测试、审查。产物行按“阶段编号 → 类型与名称 → 状态圆点”展示；目录不显示编辑锁图标，产物的只读或可编辑状态只在对话输入区的文件选择菜单中提示。

**对话影响产物**：创建默认对话时，首个获得编辑权的产物进入“进行中”。后续工作流分析或用户从输入框明确加入新的可写产物时，同一对话可以取得更多产物的编辑权，并分别把这些产物推进到“进行中”；计划中的静态依赖关系本身不自动授予编辑权。

**产物行操作**：产物视图只是对话的快捷入口。尚无对话的灰色“未开始”产物整行可点击，点击后打开创建确认弹框，不额外显示对话图标；已有对话后才显示更多菜单，菜单内按默认优先列出相关对话，并提供“基于当前产物新建对话”。

**产物写锁**：一个产物只能由其默认对话编辑。其他对话可以把该产物作为消费上下文读取，但不能修改。

## 顶部阶段与版本操作

顶部旅程固定为“分析 → 计划 → 开发 → 测试 → 审查 → 验收”，版本号下拉和“生成版本”按钮紧跟在验收阶段之后，作为旅程的最后动作。右侧工作区只有一个三档布局控制器：隐藏、分栏、全宽覆盖可直接选择；右侧面板可见时，控制器始终贴在该面板的左边线，分栏状态仍保留中间分隔线的拖拽微调宽度；仅隐藏状态把控制器贴在最右边缘。顶部和 Tab 栏不再放置重复的右侧面板开关或关闭按钮。验收阶段右侧面板新增“应用预览”Tab，承载应用根预览。验收预览不提供泛化的“返回对话”，用户只有“验收通过”或填写意见后“不通过并进入对话”两条明确路径，浏览器页签仍与“应用文件”分离。验收意见输入只服务不通过分支，Enter 提交、Shift+Enter 换行；验收通过不要求填写意见。提交意见进入独立的验收对话，由验收 Agent 先评估反馈是否超出当前基线，再决定沿当前对话处理还是进入新的需求迭代。验收阶段不创建正式文档或独立面板；只有当前需求和项目计划有效、所有开发产物完成、最新测试报告合格、最新审查报告通过且用户明确验收通过时，生成版本按钮才可用。

## 原型权限优先级

产物访问状态按以下顺序判定：

1. 尚未到达产物所属阶段：不可用。
2. 当前版本已经生成或正在查看历史版本：只读。
3. 当前工作台不在产物所属阶段：只读。
4. 当前对话不是产物的默认对话：只读。
5. 以上限制均不存在：可编辑。

开发缺陷返修时，测试报告作为开发对话的只读输入资源，不改变其产物归属；测试 Agent 也不因关联缺陷而取得开发代码写权限。

## 关键旅程

**新建应用旅程**：新建应用并创建迭代中的 v1.0 → 产品 Agent 生成并确认需求文档 → 项目 Agent 生成并确认项目计划 → 刷新页面/接口/实体清单 → 研发 Agent 完成开发、单元测试和开发自验证 → 测试 Agent 生成第一轮测试报告 → 若不合格则回到受影响开发对话修复并生成第二轮合格报告 → 合格报告开放审查阶段 → 审查 Agent 生成并确认审查报告 → 自动进入验收 → 用户预览并确认通过 → 用户生成版本并锁定快照。

**回退计划并刷新产物**：用户点击已到达的计划阶段并二次确认 → 打开原项目计划对话 → 通过聊天调整项目计划 → 接受新项目计划 → 按稳定 ID 刷新开发产物清单 → 自动进入开发阶段 → 继续处理新增或受影响产物。该旅程不创建“重新制定计划”按钮或新的计划对话。

**多产物开发旅程**：用户选择页面产物 → 研发 Agent 读取页面对接口或实体的直接依赖 → 当前开发对话取得一个或多个相关产物 → 按依赖实施并分别补齐单元测试 → 检查页面调用和对话范围联调 → 当前产物完成后自动选中下一个未完成产物并弹出创建确认 → 用户确认后恢复或创建其对话 → 相关产物全部完成。

**测试缺陷循环**：测试完整应用 → 最新测试报告不合格 → 标记受影响开发产物并关联默认开发对话 → 用户返回开发阶段且对话自动附加测试报告 → 研发 Agent 修复、单测和开发自验证 → 产物待复测 → 用户返回测试阶段 → 生成新一轮测试报告；直到报告合格后才开放审查阶段。

**审查、验收与版本旅程**：最新测试报告合格 → 审查 Agent 独立审查 → 审查问题返回相关开发对话并使受影响测试结论失效，修复后重新测试和审查 → 审查通过并自动进入验收 → 用户在应用预览窗口中操作，选择“验收通过”或填写意见后“提交意见并进入对话” → 普通对话继续承接 Agent 的基线范围审核和调整 → 用户可通过“返回应用预览”再次验收 → 验收通过后版本号下拉与生成版本动作就绪 → 用户生成版本 → 固化资产并锁定版本。

## 演示剧本约束

“实现我的回检”是一个对话拥有多个产物的主要演示案例。该对话同时负责：

- 页面“我的回检”；
- 接口 `GET /api/rechecks/my`；
- 页面调用接口后的联调验证。

从页面或接口产物进入时，都必须打开同一个“实现我的回检”默认对话。对话顶部与右侧产物区域都必须同时呈现页面和接口，工作流也必须体现接口实现、页面实现以及调用联调的先后关系。

开发详细设计文档按对话生成，一条开发对话只对应一份联合设计文档；页面、接口和未来实体代码仍按各自文件分别展示。当前演示继续以页面和接口为主，实体只展示领域占位，不虚构尚未确认的实体生成链路。
