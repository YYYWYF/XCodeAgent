# 工作台原型领域规则

本文档只描述 `prototype/` 演示工程中的工作台状态、交互限制和剧本约束，不作为正式工程的架构规范。

## 核心层级

**应用**：用户持续维护和迭代的软件工程，是版本链的根。

**版本**：应用在一次完整制作周期结束后形成的不可变资产快照。版本生成后，原型中的所有产物、对话输入和工作流操作均应只读；新变更只能发生在后续迭代版本中。

**阶段**：单个版本内依次发生的设计、开发、审查状态，每个阶段只允许调度其专属 Agent。进入后续阶段后，前序阶段产物只读；回退阶段需要二次确认，向后推进不需要确认。

**产物**：SDD 流程要求完成的正式应用资产，包括需求文档、项目计划、页面、接口和审查报告。产物状态统一为未开始、进行中、已完成。

## 对话与产物

**对话**：承载 Agent 上下文和工作流的 Session。一个对话可以生成并拥有多个产物，也可以只读引用其他产物。

**默认对话**：持有某个产物唯一编辑权的对话。从产物树选择产物时，应进入该产物的默认对话；多个产物属于同一默认对话时，选择它们不应切换到不同对话。

**正式对话的创建时机**：设计阶段的“应用设计”对话由欢迎页“开始应用设计”这一人工动作授权创建；开发阶段不按计划顺序静默预建对话。首次进入开发阶段时，用户必须先从弹框选择一个产物，确认后才创建该产物的默认对话并取得写锁。此后直接点击尚无对话的灰色“未开始”产物，也必须先弹框确认；只有确认动作才能创建对话并把该产物推进到“进行中”。普通空白对话仍在收到 Agent 回复后才进入目录。

**开发阶段的推进方式**：开发产物没有默认执行顺序。首次选择使用应用产物树，适配大量页面与接口；完成任一产物后保持当前对话，不自动跳到下一个产物。全部开发产物完成后弹框询问是否进入审查，只有用户确认后才创建“代码审查”对话并推进阶段。用户暂缓后弹框不再自动打扰，但顶部阶段条的审查节点保持可点击，点击可重新打开确认弹框；“是否具备进入条件”与“当前所在阶段”是两回事，未具备进入条件的阶段保持不可点击。

**产物状态机**：状态只能按“未开始 → 进行中 → 已完成”单向推进。颜色、文字和可选状态只反映产物自身状态；对话加载、工作流执行、目录刷新等瞬时状态不得让产物降级、失去选择能力或闪回“未开始”。

**目录信息顺序**：顶部阶段条、产物视图和对话视图统一使用 1/2/3 表示设计、开发、审查。产物行按“阶段编号 → 类型与名称 → 状态圆点”展示；目录不显示编辑锁图标，产物的只读或可编辑状态只在对话输入区的文件选择菜单中提示。

**对话影响产物**：创建默认对话时，首个获得编辑权的产物进入“进行中”。后续工作流分析或用户从输入框明确加入新的可写产物时，同一对话可以取得更多产物的编辑权，并分别把这些产物推进到“进行中”；计划中的静态依赖关系本身不自动授予编辑权。

**产物行操作**：产物视图只是对话的快捷入口。尚无对话的灰色“未开始”产物整行可点击，点击后打开创建确认弹框，不额外显示对话图标；已有对话后才显示更多菜单，菜单内按默认优先列出相关对话，并提供“基于当前产物新建对话”。

**产物写锁**：一个产物只能由其默认对话编辑。其他对话可以把该产物作为消费上下文读取，但不能修改。

## 原型权限优先级

产物访问状态按以下顺序判定：

1. 尚未到达产物所属阶段：不可用。
2. 当前版本已经生成或正在查看历史版本：只读。
3. 当前工作台不在产物所属阶段：只读。
4. 当前对话不是产物的默认对话：只读。
5. 以上限制均不存在：可编辑。

## 演示剧本约束

“实现我的回检”是一个对话拥有多个产物的主要演示案例。该对话同时负责：

- 页面“我的回检”；
- 接口 `GET /api/rechecks/my`；
- 页面调用接口后的联调验证。

从页面或接口产物进入时，都必须打开同一个“实现我的回检”默认对话。对话顶部与右侧产物区域都必须同时呈现页面和接口，工作流也必须体现接口实现、页面实现以及调用联调的先后关系。

开发详细设计文档按对话生成，一条开发对话只对应一份联合设计文档；页面与接口代码仍按各自文件分别展示。
