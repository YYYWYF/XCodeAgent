# 工作台原型领域规则

本文档描述 `prototype/` 演示工程当前采用的工作台状态、对话关系、Workflow 边界和测试准备规则。它是改版后原型的统一规则，不作为正式工程已经实现的架构声明。

## 一、本次重构结论

本次改版用以下四条新规则替代旧原型规则：

1. **对话不再拥有产物编辑权。** 产物和代码文件由活动 Workflow 的 DAG/Task 范围临时控制写入；对话只负责用户交互、任务发起和状态呈现。
2. **每个阶段只有一个阶段主对话。** 开发和测试阶段在主对话之外增加二级对象清单；点击对象只切换当前 Workflow 目标和右侧内容，不创建或切换产物专属对话。
3. **业务测试用例提前异步准备。** ProductPlan 确认后，用户先选择“异步任务”或“潮汐任务”，用例队列整体进入对应任务系统；开发期间持续生成，顶部测试阶段的数量芯片动态绑定用例所在队列并可直接打开该系统抽屉，右侧“测试用例”Tab展示详情。开发完成即可进入测试，单条用例只有在生成并校验后才可执行。
4. **开发阶段代码实现通道化。** 前台 Workflow 只负责“设计与选择”：详细设计确认后，工作流轨迹挂出「选择执行方式」节点（交互卡内嵌在节点上，提供“同步任务 / 异步任务 / 潮汐任务”三个选项，解释话术收进注释图标）。选“同步任务”则在当前对话当场播放 Build DAG、代码生成、代码变更确认、构建及单元检查和页面预览节点，执行记录沉淀在异步任务系统；选“异步任务”或“潮汐任务”则在对应任务系统创建 `artifact_implementation` 后台任务并立即结束前台运行、释放会话锁，由后台无人值守执行到「已完成」后由任务中心和开发产物目录承载人工验收。

旧版以下规则已经废止：

- “一个产物只能由其默认对话编辑”；
- “开发阶段按产物创建多条默认对话”；
- “点击产物必须跳回所属对话”；
- “静态依赖或输入框附件用于扩张对话写权”；
- “测试阶段只有一份测试报告，不展示用例清单”；
- “普通新建对话可以承接正式代码修改”。

## 二、核心层级

**应用**：用户持续维护和迭代的软件工程，是版本链的根。

**版本**：一次完整制作周期形成的不可变资产快照。版本生成后，当前版本的产物、Workflow 操作和对话输入只读；新变更只能发生在后续迭代版本。

**阶段**：单个版本依次经过分析、计划、开发、测试、审查和验收。版本生成是验收后的确定性终态动作，不是第七阶段。

**阶段主对话**：当前阶段唯一的正式交互入口。它可以先后启动多条 Workflow，汇总阶段状态并引导用户满足准入条件，但它本身不拥有文件或产物写锁。

**Workflow 实例**：一次具有明确目标、DAG、任务范围和终态的正式执行。一个阶段主对话可以承载多条 Workflow；一条 Workflow 可以交付多个强关联产物，并在 DAG 内并行执行路径不冲突的任务。

**产物**：工作区中的长期业务事实。分析阶段产出需求文档，计划阶段产出项目计划，开发阶段交付页面/接口/实体及代码，测试阶段执行测试用例并记录结果与缺陷，审查阶段交付审查报告，验收阶段不新增正式文档。

**代码文件**：实现一个或多个产物的工程事实。文件不属于阶段主对话；每次修改必须归属于当前 Workflow 的具体任务和允许路径。

## 三、对话、Workflow 与产物关系

关系固定为：

```text
一个阶段主对话 → 多条 Workflow
一条 Workflow → 一个或多个相关产物
一个产物 → 历史上可被多条 Workflow 依次修改
一个产物在同一时刻 → 只允许一条活动 Workflow 写入
```

阶段主对话保持稳定：用户在开发清单中选择页面或接口时，只更新 Workflow 当前目标，不切换聊天 Session。开发阶段右侧默认打开“开发产物”Tab；进入编码 Diff 时临时切到“应用文件”，页面预览仍回到“开发产物”内容区，不使用独立浏览器。Workflow 运行、暂停、确认、失败、恢复和完成都继续投影在同一阶段主对话中。

产物上下文和文件范围由当前 Workflow 根据正式计划、DAG、目标文件和允许路径确定；对话不维护产物附件、归属或写锁。

## 四、阶段与主对话职责

### 1. 分析阶段 · 产品 Agent

分析主对话澄清业务目标、角色、流程和功能边界，只维护需求文档。需求文档生成或修改后必须由用户明确确认；澄清回答不能替代文档确认。

### 2. 计划阶段 · 项目 Agent

计划主对话只读取已确认需求并维护项目计划。项目计划是页面、接口、实体和直接依赖关系的唯一来源。ProductPlan 确认后弹出测试用例生成任务类型选择：异步任务使用常规算力资源并消耗码豆余额，潮汐任务使用极算平台闲时算力资源、不消耗码豆但优先级较低；选择后启动后台业务测试用例准备。上游计划修订时，受影响开发对象和测试用例同步失效。

### 3. 开发阶段 · 研发 Agent

开发主对话负责页面、接口和实体实现，以及单元测试、调用检查、构建和基础启动验证。开发主对话按未完成页面自动投放“模板选择 / 详细设计”卡；用户确认模板后启动该页面的 Workflow，Workflow 只在前台完成详细设计，随后在工作流轨迹末尾挂出「选择执行方式」待输入节点（执行方式选择卡内嵌在该节点上，不单独成块）；涉及依赖接口时，页面产物选择完成后会接着挂出「选择接口执行方式」节点，由用户在“同步任务 / 异步任务 / 潮汐任务”中分别为两个产物选择——选后台通道时在对应任务系统创建 `artifact_implementation` 后台实现任务并立即结束前台运行、释放会话锁，主对话马上投放下一个未接管对象的模板卡；选同步任务则当场在对话内播完生成节点（经「确认代码变更」接受 Diff），记录沉淀在异步任务系统。页面及其直接依赖接口由同一任务联合交付。当前演示剧本固定为“回检介绍”页面，以及“我的回检”页面 + `GET /api/rechecks/my` 接口：我的回检的详细设计一次覆盖页面与依赖接口两个产物，执行方式按产物各选一次，生成代码任务同样是两个（页面任务、接口任务），各自进所选通道。

两套任务系统从存储到调度完全独立：异步任务（常规算力域）与潮汐任务（闲时算力域）各有独立流水、独立入口与抽屉，引擎逐系统推进、互不等待，同一系统内一次只执行一个任务——用例生成与代码实现都在本系统队列里按顺序逐个推进。后台实现任务按“排队 → 执行 Build DAG → 生成代码 → 构建及单元检查 → 启动页面预览 → 完成”无人值守推进；同步任务由剧本在对话内按同一阶段顺序当场推进（生成代码后经「确认代码变更」接受 Diff），引擎不调度同步任务；其记录仅用于产物状态推导，不进入任何队列抽屉，验收入口由对话输入框的「待验收」快速选择承载。

工作流底层采用“一套 DAG、多种表现段”的模型（`mock/workflowGraphs.ts`）：真实工程的底层 DAG 庞大交织，对话面板只呈现本次选中执行的一段。开发工作流注册了一张完整 DAG（页面设计分支与接口设计分支交织，汇聚到“选择执行方式”，再分出同步构建链与后台构建链，完成后进入验收段并预留验收调整回流），剧本只负责从 DAG 选段播放——详细设计段、同步任务段、派发收口与产物验收段的节点标题均以 DAG 为唯一来源，因此不要求界面展示的节点一致，但同一种工作流的底层图是一套。验收段回主对话执行：先播放“打开产物预览”节点，再挂“确认验收”待输入节点，确认后节点收口。任务完成即落“已完成”终态；完成后的后续步骤（如产物验收）以入口形式挂在任务条目上，点击在阶段主对话启动对应工作流——验收工作流打开右侧预览并承载确认，确认后产物标记完成、测试依赖解除。任务中心和产物状态是权威入口，完成通知不向对话末尾插入迟到的 Assistant 消息。

开发对象分别维护“未设计 → 设计中/实现排队/实现中/待验收 → 已完成/失败”状态。所有当前开发对象完成（验收通过）并通过开发门禁后即可进入测试阶段；尚未生成的测试用例在测试用例工作台中置灰，直到准备完成。

### 4. 测试阶段 · 测试 Agent

测试主对话从完整应用视角执行已经确认的业务测试用例。测试阶段先运行“非功测试工作流”（启动测试、非功能检查等少量节点），该工作流不选择或改变任何业务用例状态。随后按目录顺序为每条业务用例创建一条“用例测试工作流”。授权卡出现即表示当前用例 Workflow 已启动，目录将对应的单条用例标为紫色进行中；卡片只负责让用户确认是否执行这一条用例。确认后依次执行测试脚本、生成缺陷清单；有缺陷时继续调度返修节点并完成回归测试，无缺陷时直接结束当前 Workflow。当前用例的缺陷、修复状态和执行证据同步显示在右侧详情中。Workflow 完成且缺陷全部关闭后，该用例才标为绿色完成并进入下一条；尚未开始的用例始终保持灰色。用例执行本身不调用模型；执行器按依赖和运行资源进行有界并发，并记录证据。

失败用例生成结构化缺陷，关联用例、证据、受影响开发产物和代码 revision。缺陷修复作为用例测试 DAG 中的返修节点被调度，修复后必须执行对应回归节点；全部必需用例取得终态且阻塞缺陷关闭后，才允许进入审查阶段。

### 5. 审查阶段 · 审查 Agent

审查主对话只在测试门禁通过后进入，独立检查代码规范、安全、健康度、可维护性、计划一致性和交付完整性。审查 Agent 默认只读代码，只维护审查报告；审查问题通过开发主对话创建返修 Workflow。

### 6. 验收阶段 · 产品 Agent

验收主对话辅助用户依据需求文档和应用预览完成确认。验收阶段不新增正式文档；不通过意见由验收主对话判断是否属于当前基线，必要时进入新的需求迭代。

## 五、阶段二级对象清单与左侧导航

页面层级为：

```text
阶段主对话 → 当前阶段对象清单（按需出现） → 右侧文件/预览面板
```

- 分析阶段：没有二级清单，右侧直接展示需求文档。
- 计划阶段：没有二级清单，右侧直接展示项目计划。
- 开发阶段：展示页面、接口和实体清单及各自完成状态。
- 测试阶段：展示测试用例分组、执行状态和缺陷清单。
- 审查阶段：没有二级清单，右侧直接展示审查报告。
- 验收阶段：没有二级清单，右侧直接展示应用预览和验收动作。

二级清单只用于存在多个需要独立选择、执行或验收对象的阶段。它不是对话目录，也不提供“基于产物新建对话”操作。

二级清单属于阶段状态，不再长期占用左侧会话导航。基础原型的左侧固定为窄功能栏，上下两组：顶部是抽屉类入口「临时对话」和「后台任务」，一道横线收尾；用户功能入口「文件」「技能」「设置」与底部头像贴近、沉底成组。「后台任务」与顶部测试用例数量芯片是同一队列抽屉的两个入口；存在待验收实现任务时，入口悬浮文案直接给出“N 项待验收”。测试用例明细只通过该抽屉或右侧“测试用例”Tab查看，不在左侧功能栏重复放置入口。阶段主对话、对象选择和 Workflow 进度均在中间主工作区或右侧工作台中呈现。左侧图标统一提供 hover 文案，不承担会话切换。

## 六、临时对话

临时对话是阶段主对话的辅助空间，负责只读问答、代码解释、方案讨论和即时问题分析。它不启动写入型 Workflow，也不改变阶段、主对话或产物状态。

如果用户在临时对话中提出修改要求，系统只形成结构化任务建议，并提示转到当前阶段主对话创建正式 Workflow。临时对话不会静默升级权限。

临时对话通过统一辅助抽屉呈现：

- 入口位于左侧窄功能栏顶部；
- 抽屉与后台任务队列抽屉完全同款同位：420px 面板从左侧菜单栏右侧滑出，头部为图标徽标、标题与一句话说明，不遮挡菜单栏、顶部栏与右侧面板；
- 两个抽屉同一时间只能打开一个：打开任一个时自动关闭另一个；
- 抽屉覆盖主对话区域左侧，右侧文件/预览面板保持可见；
- 关闭后恢复主对话原位置和运行状态；
- 基础版本只保留一个活动临时对话，支持清空后新建；
- 临时消息不进入阶段主对话的 Workflow 上下文。

## 七、异步业务测试用例准备

### 1. 与单元测试的边界

异步生成的是业务场景、页面与接口组合路径、异常路径和数据校验用例，不替代开发阶段根据代码变更生成并执行的前后端单元测试。

### 2. 触发与执行

1. RequirementSpec 提供业务目标、角色、流程和验收标准。
2. 需求文档和项目计划都带有预计测试用例概要（总量、业务场景和覆盖范围）；ProductPlan 确认后弹出任务类型选择，明确展示预计生成的用例总量。用户选择异步任务或潮汐任务后，后台创建独立测试用例准备任务，按业务模块和稳定场景分批调用模型。
3. TechnicalPlan 确认后，补齐页面、Endpoint、Schema 和实体绑定等可执行引用；能够确定性补齐的内容不重复调用模型。
4. 开发阶段正常推进，不等待后台生成完成。
5. 每批完成后立即校验并保存；单批失败只重试该批，不丢失其他结果。
6. 全部用例生成和校验完成后自动进入“已就绪”，不增加用户重复确认步骤。

后台状态为：

```text
排队中 → 生成中 → 校验中 → 已就绪
                    └→ 失败
上游正式产物变化 → 已失效 → 重新排队
```

用例集合绑定 RequirementSpec、ProductPlan 和 TechnicalPlan 的当前 revision。上游正式产物修订后，受影响用例不得继续用于测试准入。

### 3. 顶部数量芯片、后台任务抽屉与测试用例工作台

顶部测试阶段只展示用例数量，不再显示“待确认”“已就绪”等状态文案，也不额外发送 Toast 或向阶段主对话重复插入通知：

```text
测试阶段 2/6
```

数量芯片是独立于阶段控制条的任务入口：它渲染在测试阶段按钮之外，即使阶段按钮因旅程未到达而禁用，芯片从计划确认起就始终可点击。悬停数量时提示“测试用例 2/6”；点击芯片动态绑定到用例任务实际所在的任务系统——开发准入门选定异步则打开“异步任务”抽屉，选定潮汐则打开“潮汐任务”抽屉，不触发阶段切换或进入确认。点击测试阶段本身或直接进入测试阶段，才会打开右侧“测试用例”Tab；测试阶段不提供浏览器 Tab。该 Tab 复刻开发产物的“目录 + 内容”布局：左侧只展示业务测试用例树，按场景分组并展示异步生成数量，右侧展示所选用例的前置条件、执行步骤、预期结果和本轮测试结果。

后台任务完成后带后续步骤（如产物验收）时有两类配套入口：任务抽屉条目上的「验收」按钮，以及开发主对话输入框工具栏的「继续工作流」入口——像“添加文件”一样点开弹层，列出当前可以接着发起的工作流（待验收任务的验收段），点击即在主对话启动。两者复用同一条启动链路：定位产物 → 右侧打开预览 → 主对话播放验收段。同步任务在对话内确认代码变更后即交付完毕，不产生待验收，也不出现在该入口。

异步任务与潮汐任务从左侧菜单栏就拆成两个独立入口（沙漏/月亮图标；同步任务为闪电图标，仅出现在执行方式选择卡。图标语言：同步=闪电当场执行，异步=沙漏放后台慢慢跑，潮汐=闲时月亮；同步任务的验收入口在对话输入框，不在抽屉），各自滑出一个结构完全相同的队列抽屉：标题、头部徽标与入口共用同一套图标语言，从左侧菜单栏右侧滑出，不遮挡菜单栏、顶部栏与右侧面板，与临时对话抽屉同款同位、同一时间互斥打开。抽屉内 Tab 分「进行中 / 已完成」两段：进行中按队列位次编号，一次只执行一个任务、其余按顺序排队；已完成按完成先后编号沉淀。行内不重复展示所属系统（所属关系由入口承载），队列抽屉只承载后台队列任务，同步任务不出现在抽屉中。已完成任务如带后续步骤（如产物验收），条目上提供入口按钮，点击在主会话启动对应工作流。

启动测试和非功能测试属于独立的“非功测试工作流”，但不进入“测试用例”目录。业务用例生成中时，目录使用进行中状态点；未生成的单条用例置灰且不可点击，生成完成后才可逐条查看，执行器运行后将结果更新为执行中、通过或失败。测试阶段不生成测试报告文件。

异步任务系统使用常规算力队列，潮汐任务系统使用低优先级的闲时队列；单条用例依次经过排队、生成、校验三个时段。潮汐系统的总时长刻意长于开发阶段演示时长，用于呈现“开发产物已全部完成，测试用例仍在后台生成”的排队效果。生成节奏由演示常量统一控制，两套系统仅节奏与算力口径不同，交互结构完全一致。

开发产物全部完成且最后一条 Workflow 收尾后，进入测试阶段弹框立即出现，不再额外等待用例准备任务；若用例仍在后台生成，弹框展示当前生成进度并提示可先进入测试阶段，未生成的单条用例在目录中置灰不可用。

用例生成失败或失效时，右侧用例内容区提供重新生成入口；同一时间不叠加测试用例工作台与辅助抽屉。

测试工作流按目录顺序逐条推进时，必须等当前用例在后台生成队列中就绪才会出现执行确认卡；未就绪期间不产生执行状态、不生成用例 Workflow，右侧目录保持置灰。

## 八、阶段准入

阶段是否可查看、是否具备进入条件和当前正在执行哪个阶段必须分开记录。

开发进入测试至少要求：

- 当前开发对象清单全部完成（完成以用户在待验收中接受产物为准）；
- 后台实现任务的构建与单元检查通过（随任务到达待验收即视为通过）；
- 开发阶段单元测试、联调、构建和基础启动检查通过；
- 当前 revision 的业务测试用例总量已确定；未生成的用例在测试工作台中置灰，生成后再开放查看和执行。

测试进入审查至少要求：

- 全部必需用例执行完成；
- 不存在未关闭的阻塞缺陷；

测试发现缺陷时，受影响开发对象回到“进行中/待修复”，但不得抹掉其曾经完成开发的历史。修复后重新执行受影响用例及必要的应用级验证。

## 九、右侧工作区与版本规则

右侧按阶段提供“开发产物”“测试用例”“应用文件”和必要时的“浏览器”能力。开发阶段默认进入“开发产物”，测试阶段默认进入“测试用例”，这两个阶段都不提供浏览器 Tab；分析/计划阶段也不提供浏览器 Tab。开发产物和测试用例都采用“目录 + 内容”双栏，目录宽度受控，层级可折叠，右侧根据当前叶子对象展示页面预览、接口调试或用例详情。只有计划阶段确认后，顶部开发阶段旁才显示开发产物完成比例，顶部测试阶段旁才显示预计用例生成数量；计划确认前两个数字均不出现。开发目录中的产物展示领域状态点：未开始（灰）、实现排队（空心紫）、实现中（紫色呼吸）、待验收（紫点外圈光晕）、已完成（绿）、失败（红）；待验收页面即可在内容区打开预览，验收完成后保持可预览。测试目录中的用例展示生成状态点；同一版本内已确认完成的产物状态只增不减，目录刷新或下一条 Workflow 不得回退完成数。点击对象只选择当前 Workflow 或测试执行对象，不切换阶段主对话。开发阶段不再出现代码 Diff 授权页签；审查报告的 Diff 确认可临时切换到“应用文件”。应用文件使用同一源码编辑/只读视图；Markdown 文档不自动切换预览态，阶段主对话始终保持不变。

版本生成后固化当前资产快照并锁定为只读。只有需求和计划有效、开发对象完成、测试门禁通过、审查通过且用户明确验收通过时，才允许生成版本。历史版本不恢复写入型 Workflow，也不允许临时对话获得写权限。

## 十、关键旅程

### 新建应用

创建迭代版本 → 分析主对话确认需求文档 → 计划主对话确认项目计划并启动后台用例生成 → 开发主对话确认详细设计并派发后台实现任务、验收待验收产物 → 进入测试主对话检查已生成用例并持续等待其余用例 → 用例测试 DAG 执行、修复缺陷并回归 → 审查主对话确认审查报告 → 用户验收 → 生成只读版本。

### 多产物开发

开发主对话投放首个未完成页面的模板选择卡 → 用户确认模板 → 前台 Workflow 完成详细设计并在轨迹末尾挂出「选择执行方式」节点 → 用户在内嵌选择卡上选“同步任务 / 异步任务 / 潮汐任务”：选后台通道则在对应任务系统派发后台实现任务、会话锁立即释放，主对话自动投放下一个页面的模板选择卡；选同步任务则当场在对话内播完生成节点并把记录沉淀到异步系统 → 两套任务系统并行、系统内串行地执行 Build DAG、代码生成、构建/单测和页面预览 → 任务完成后条目提供「验收」入口 → 点击在主会话启动验收工作流，右侧打开预览、对话区确认验收 → 产物标记完成；两条实现任务完成后开发门禁开放。全过程不创建产物专属对话，也不向对话插入迟到的完成通知。

### 临时问答

用户打开临时对话抽屉 → 只读询问当前文件或产物 → 关闭抽屉返回开发主对话；如果需要修改，生成任务建议并转交主对话，临时对话本身不执行 Workflow。

### 异步测试准备

ProductPlan 确认 → 顶部测试阶段显示生成数量 → 用户在开发过程中按需打开“测试用例”Tab查看分组进度 → 后台分批生成和校验 → 用例可逐条查看 → 开发门禁完成后进入测试 → 确定性执行全部用例并记录结果与缺陷。
